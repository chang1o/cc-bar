## 1. Popover

### 1.1 整体规格

| 项 | 值 |
|---|---|
| 宽 | 340pt(固定) |
| 高 | auto;随启用 Provider 数量增长,零服务 ~110pt(提示空状态) |
| 圆角 | 18pt(`NSPopover` 系统提供,不自绘) |
| 材质 | `.popover`(系统) |
| 锚点 | 菜单栏图标下方,7pt arrow notch 朝上 |
| 出现动画 | 系统默认(`MenuBarExtra(.window)` 提供) |

### 1.3 Header

- **容器**:HStack(spacing 4),padding `14pt 上 / 12pt 左右 / 12pt 下`(到 separator)。
- **左侧**(VStack,line-height 1.1):
  - `Usage` — 13pt .semibold
  - `用量 · refreshed 32s ago` — 11pt secondary
    - `refreshed {n}s ago` / `{n}m ago` / `{n}h ago`,取所有已启用主 Provider 中**最近**一次成功时间;无成功时显示 `用量 · 等待数据`。
- **右侧**(HStack,spacing 4):
  1. **status dot** — 7pt 圆点(live/stale/offline),颜色按 设计风格 §4.3,hover tooltip `Live · 在线` 等。
  2. **Refresh** — `arrow.clockwise` 13pt,按钮 `26pt × 22pt` 圆角 5pt,hover 浅灰背景(`Color.primary.opacity(0.08)`)+ 手型光标。点击触发 `appState.refreshNow()`,图标旋转 360° / 700ms ease-in-out。**不禁用**:`AppState.refreshNow()` 内部已做 in-flight 去重,不会重复发请求,刷新开始后由 `isRefreshing` 驱动转圈。
  3. **Open Statistics** — `chart.bar.xaxis` 13pt,同尺寸按钮。点击先设 `appState.mainTab = .stats` 再 `openWindow(id: "main")`,Popover 关闭。
  4. **Settings** — `gearshape` 13pt,同尺寸按钮。点击先设 `appState.mainTab = .settings` 再打开主窗口,与 ⌘, 命令行为一致,总是落到设置 tab。
  5. **Quit** — `power` 13pt,同尺寸。点击 `NSApp.terminate(nil)`,hover tooltip `Quit · 退出`。

> 设计依据:用户反馈一级操作(设置 / 刷新 / 统计 / 退出)藏在 kebab + footer 里不直观,统一拉到顶部图标行,降低点击层级。Quit 早期收在 `ellipsis` 菜单需要点两次,后续也拉平为一级图标。

- **separator**:0.5pt 全宽,`.separatorColor`。

### 1.4 服务 block(Codex / Claude / Antigravity 共用结构)

整个 block 用 `14pt 上下 / 16pt 左右` padding。

#### 1.4.1 Service header row(HStack,gap 9pt)

| 元素 | 规格 |
|---|---|
| 服务 tile | 22pt × 22pt squircle(6pt 圆角),服务识别色填充,白色 logo 14pt 居中。详见 设计风格 §11.2。 |
| 服务名 + plan(VStack,line-height 1.08) | `Codex` 13pt .semibold kerning -0.1<br>`OpenAI · Plus` 11pt secondary opacity 0.75(按 `email · plan` 拼接,隐私模式隐藏 email,兜底品牌名) |
| Spacer | — |
| 服务状态圆点 | 6pt 圆,贴 Spacer 后,行尾。颜色按 statuspage indicator(none 绿 / minor 黄 / major 橙 / critical 红 / maintenance 蓝),`unknown` 或未拉到时不显示。受设置项 `showServiceStatus` 控制,tooltip 显示 statuspage description + 相对更新时间。 |

#### 1.4.2 Body row(HStack,alignment center,gap 16pt,marginTop 12pt)

**左栏:主要额度大数字 + 动态窗口标签**(VStack,center,spacing 4)

- 第一行:HStack(firstTextBaseline,spacing 0),`42` 32pt .semibold monospacedDigit kerning -0.8 + `%` 16pt .semibold(状态色;无快照时 `.secondary` 显示 `--`)。
- 第二行:固定短标签,不随 App 语言切换,9pt .semibold kerning 0.5 .quaternary:五小时额度统一显示 `5HOUR`;周额度 Codex 显示 `WEEKLY`、Claude 统一显示 `ALL`;`modelWeekly` / `unknown` 显示模型名(空则 `MODEL` / `CURRENT`)。
- 状态色规则按 设计风格 §4.3。

**右栏:进度条 + reset / 费用两行**(VStack,leading,spacing 8,flex 1)

1. **ProgressBar**:高 7pt(圆角 3.5pt),状态色填充 + `.quaternarySystemFill` 轨道。进度 = `primaryWindow.remainingPercent / 100`。
2. **文本行 1**(HStack,spacing 0):
   - 左:`ResetTimeText` 紧凑格式 `2h18m`(11pt .medium primary),悬停行内切换相反格式(剩余时长 ↔ 具体时刻,当天 `HH:mm`,跨天 `MM-dd HH:mm`);无重置时间显示 `—`。
   - 右(仅 Codex / Claude;Antigravity 隐藏):`today · 今日` 与 `this week · 本周` 两项费用,`$12` 11pt .medium primary monospacedDigit(取整美元,`<$1` 用于 0 ~ 0.99)+ 10pt quaternary 标签,HStack spacing 10。
3. **文本行 2**(HStack,spacing 0):
   - 左:`reset · 重置` 9.5pt quaternary。
   - 右(仅 Codex / Claude):`cost · 花费` 9.5pt quaternary。

#### 1.4.3 Block 间分隔

- 相邻 Provider 之间:0.5pt 横线,**左右各 inset 16pt**。
- 最后一个 block 之后无 footer,由系统 `NSPopover` 圆角承接底边。

#### 1.4.4 空状态 / 错误状态

- `snapshot == nil` 且 `error == nil`:左栏显示 `--` 32pt `.secondary`,右栏进度条空轨道 + reset 显示 `—`,无额外文案。
- `error != nil`:block 底部追加一行,`Color.orange` + 前置 `exclamationmark.triangle.fill` 图标(10pt),`shortError` 截断 110 字,lineLimit 2。左栏按最后一次成功快照继续显示(`appState` 不清空快照)。其他账号行的错误态样式相同。
- 服务在 Settings 里被关闭(`showXxx == false`):**整个 block 不渲染**。
- 全部服务关闭:Popover 只显示 header + 中部两行占位 `No services enabled · 未启用任何服务`(12pt .medium secondary)+ `Enable a service in Settings → Accounts · 到「设置 → 账号」开启`(11pt tertiary),垂直 padding 24。

#### 1.4.5 Antigravity 差异

- 展示两组独立额度：主区块为 `Claude + GPT models` 的 5H/WK（与 Codex/Claude 格式一致，菜单栏和悬浮窗仅使用此数据），底部额外展示 GM 行（`Gemini Models` 5h）和 GW 行（`Gemini Models` 周），风格对齐 `compactLimitRow`（9pt 标签 + 2.5pt 进度条 + 10.5pt 百分比 + 重置时间）。
- 服务 tile 使用 `AntigravityAccent`;副标题显示 Google 账号邮箱与 plan,隐私模式下隐藏邮箱。
- 不显示 today / this week cost;App 未运行或 IDE 只能提供部分数据时保留缓存并显示短错误。
- `Gemini Models` 组数据仅影响 Popover 展示，菜单栏百分比、悬浮窗和统计页仍只使用 `Claude + GPT models` 的 5H/WK。

### 1.5 Footer(已废弃)

> 原方案的 footer(左侧 `Open Statistics` 按钮 + 右侧 refresh + kebab)已**完全移除**。所有一级操作上移到 §1.3 Header 的图标行,刷新进度通过 header 刷新图标自身旋转 + disabled 表达。本节保留仅为历史参考,新实现不要再引入 footer。

### 1.6 交互

| 触发 | 行为 |
|---|---|
| 点 header `chart.bar.xaxis` | `mainTab = .stats` 后 `openWindow(id: "main")`,Popover 关闭 |
| 点 header `arrow.clockwise` | 触发 `appState.refreshNow()`,旋转 360° / 700ms;按钮不禁用(`refreshNow` 内部 in-flight 去重) |
| 点 header `gearshape` | `mainTab = .settings` 后打开主窗口 |
| 点 header `power` | `NSApp.terminate(nil)`,退出 App |
| 点 service block 任意空白 | 暂不响应(后续可定位主窗口到对应服务 scope) |
| 点 Popover 外 | Popover 关闭(系统默认) |
| Esc | Popover 关闭(系统默认) |
| ⌘R(focus 在 Popover) | 触发 refresh |
| 鼠标悬停任意图标按钮 | 浅灰圆角背景 + 手型光标(详见 设计风格 §11.9) |
| 鼠标悬停 reset 时间 | 行内切换相反格式:设置为剩余时长时显示具体时刻(当天 `HH:mm`,跨天 `MM-dd HH:mm`);设置为具体时间时显示剩余时长。hover 热区略大于文字本身,避免鼠标遮挡数字才触发。 |

### 1.7 数据来源对照

| UI 字段 | 数据源 |
|---|---|
| 主要额度百分比(左栏大数字) | `appState.{codex,claude}Quota?.primaryLimit?.window.remainingPercent` |
| 主要额度标签 | `primaryLimit.kind` 映射为固定短标签：五小时 `5HOUR`；周额度 Codex 为 `WEEKLY`,Claude 为 `ALL`,不随 App 语言切换 |

| 次要额度 + 模型额度 | `secondaryLimit`（去重后）+ Claude `modelLimits` |
| today / this week 费用 | `UsageAggregator` 今日 / 本周 cost 总和（取整美元显示） |
| Header refreshed time | 所有已启用服务 `refreshState.lastSuccessAt` 取 max |
| 状态点 live/stale/offline | 现有 `headerState` 三态判定 |
| Plan 副标(`OpenAI · Plus`) | `appState.{codex,claude,antigravity}Account?.planType / subscriptionType`,按 `email · plan` 拼接,隐私模式隐藏 email |
| 服务 tile logo | `Resources/Logos/codex.svg / claude.svg / antigravity.svg` |
| GM 行(Gemini 5h) | `appState.antigravityQuota?.geminiWindow` |
| GW 行(Gemini 周) | `appState.antigravityQuota?.geminiWeekly` |

## 2. Floating HUD

### 2.1 整体规格(默认变体:Two-row pill)

| 项 | 值 |
|---|---|
| 宽 | auto,最小 168pt |
| 高 | auto(两行 pill 约 50–60pt) |

| 背景 | 实色压底 + `.popover` 毛玻璃 + 0.5pt hairline 描边(`Color.primary.opacity(0.12)`),见 设计风格 §12.3 |

### 2.2 内容结构(variant 1)

VStack,spacing 7pt。每行结构如下:

```
[●]  ████████░░░░░░░░░░  [42%]
[●]  ███████████████░░░  [78%]
 18pt    flex,4pt bar     34pt
```

| 元素 | 规格 |
|---|---|
| 左侧 logo tile | `ServiceTile` 18pt 圆角 5pt,服务色填充 + 内嵌 logo 12pt(`codex.svg` / `claude.svg`),logo 加载失败时回退字母 `C` / `K` |

## 3. Statistics 主窗口

系统级入口：从 Dock、应用程序、Launchpad 或 Raycast 启动 / 重新打开 CCBar 时，主窗口置前并切到 Statistics；`SMAppService` 开机自动启动保持静默，首次启动仍优先显示 Onboarding。

### 3.1 整体规格(默认视图:Overview)

| 项 | 值 |
|---|---|
| 宽 / 高 | 默认 1600pt × 1100pt,最小 1040pt × 520pt,可调 |
| 圆角 | 12pt(系统 Window) |
| 顶栏 | 无系统 toolbar;时间范围 segmented Picker 在 Overview 画布顶部右对齐(见 §3.2) |
| 布局 | Sidebar(200pt) + Main canvas |

### 3.2 Top bar(Overview 画布顶部)

- 无系统 `toolbar`(主窗口只有 TabView)。Overview 画布顶部一行右对齐:
  - 扫描中显示 `ProgressView` + `Recalculating usage… · 正在重新计算用量…`(11.5pt secondary),否则不占位。
  - 右侧 SegmentedControl,9 个段:
    `Today / Yesterday / Week / Month / Year / 7d / 30d / All / Custom`
    对应 03 词表:`今天 / 昨天 / 本周 / 本月 / 本年 / 7 天 / 30 天 / 全部 / 自定义`(中文不显示在控件里,而是在 Sidebar Service 组下方语境中)。
    - 容器:2pt padding,圆角 7pt,bg `rgba(0,0,0,0.06)`(浅)/ `rgba(255,255,255,0.08)`(深)
    - 段:`3pt 上下 / 10pt 左右`,高 22pt,圆角 5pt
    - active:浅色 `#fff` + 微阴影 `0 0.5 2 rgba(0,0,0,0.18)`;深色 `rgba(120,120,128,0.55)` + 同阴影;字体 .semibold,letterSpacing -0.05
  - **SwiftUI 推荐**:直接用 `Picker(.segmented)`。如果系统外观不够还原,再自绘。

### 3.3 Sidebar(200pt 宽)

- 整体:`.sidebar` material,padding `14pt 上下 / 12pt 左右`,内部 VStack gap 16pt。
- 右侧 0.5pt separator(分隔 sidebar 与 main)。

**两个 Group**,每个 group:

- **Group title**:10pt .semibold letterSpacing 0.4 tertiary 大写,padding `0pt 6pt 4pt 6pt`,格式 `SERVICE · 服务`。
- **Items**(VStack,gap 1pt):每行 `5pt 上下 / 8pt 左右`,圆角 6pt,12pt .medium,**active 行**:accent 背景 + 白字。

| Group | Items(EN / CN) | 说明 |
|---|---|---|
| Service · 服务 | All / Codex / Claude Code / Pi / OpenCode | All 用 8pt 空占位;服务项用 8×8 squircle(radius 2,服务色)作为前缀色块。仅列出「设置 → 统计服务」中启用的服务;关闭项不在侧栏出现,若当前选中项被关闭则自动回退到 All |
| View · 视图 | Overview / Conversations / Timeline / Cycles | 各带 13pt icon；Cycles 使用 `arrow.triangle.2.circlepath`。Cycles 仍保留全部已启用服务筛选项，但选择不改变周期内容 |

> 时间范围切换**不在侧栏**：Overview / Conversations 使用 §3.2 的日期范围 segmented Picker；Cycles 的当前周期区同屏展示 Weekly + 5-hour 不提供切换，历史区用自己的 segmented Picker 选「服务 × 周期类型」；Timeline 固定展示今日事件。

每行**右侧**有 10.5pt tertiary 的中文 caption(active 行 opacity 0.75,非 active 0.5)。

### 3.4 Main canvas — Overview(主视图)

- 历史表固定四列：周期 / 额度已用 / 实际 Tokens 与费用 / 用满 Tokens 与费用，最新在前。「实际」和「用满预估」各自把 Tokens（12pt mono）与费用（11pt mono secondary）上下堆叠成一格，同列上下对照；额度已用列是 11.5pt mono 百分比 + 高 3pt 迷你 `ProgressBar`（同样走 `statusColor`），让「哪个周期烧满了」一眼可见。列宽按 `周期 34% / 额度已用 16% / 两个指标列均分剩余` 分配，最小 150 / 88 / 96pt。

- Tokens 统一走 `StatsFormatter.compactToken`，中文用 `万 / 亿`、英文用 `k / M / B`；费用统一走 `StatsFormatter.tierCost` 两位小数。数据质量与可信度合并到周期单元格第二行，不占主要对比列；服务已由 Picker 和面板标题表达，周期行不重复服务名或服务色点。
- 预估可信度分 `Early · 早期`（0%～10%）、`Rough · 粗略`（10%～30%）、`Reference · 参考`（30%～80%）、`Reliable · 较可靠`（80% 以上）。数据质量 `Partial · 不完整` 不阻止推算；观察变化、Token 或费用依据为 0 时对应预估显示 `—`。
- 底部固定说明：实际用量仅含 CCBar 可读取的本机日志；用满预估按当前额度段用量与官方比例变化推算，福利重置前的实际用量会保留，但未观察周期不会补造，结果也不是官方绝对 Token / credit 上限。
