> 对应 [产品需求.md](产品需求.md)。描述当前代码的架构、模块边界与关键流程。新增功能时以本文作为入门地图，与代码不一致以代码为准。

## 1. 技术栈

| 层 | 选择 | 备注 |
|---|---|---|
| 语言 | Swift 5 language mode（当前 Xcode 工具链） | async/await + `@Observable` |
| 工程 | Xcode `ccbar.xcodeproj` | 单 target，标准 macOS App |
| UI | SwiftUI 主、AppKit 辅 | 菜单栏 label / 悬浮窗 panel 走 AppKit |
| 最低系统 | macOS 14 Sonoma+ | 依赖 `MenuBarExtra(.window)`、`@Observable`、`SMAppService` |
| 存储 | UserDefaults + JSON 文件 | 不引入 SQLite |
| 网络 | `URLSession` async/await | 标准库，无第三方依赖 |
| 图表 | `Charts`（SwiftUI） | 用于统计 tab 日趋势 |

整个工程零第三方依赖；钥匙串通过命令行 `security` 访问，避免 Keychain Services API 的多次授权弹窗。

## 3. 应用入口与窗口组合

`CCBarApp.swift` 组装三个 Scene：

1. `MenuBarExtra(.window)`：label 是自绘 NSImage 包装；content 是 `PopoverRootView`。`.task` 内执行 `appState.bootstrap()` 并把 `FloatingPanelController` 与 AppState 绑定，再根据设置同步显示。
2. `Window("CCBar", id: "main")`：主窗口，内部 `MainWindowRootView` 用 TabView 切「统计 / 设置」。
3. `Window("Welcome", id: "onboarding")`：引导窗口，`fixedSize` 禁缩放。

`AppCommands` 通过 `CommandGroup` 注入全局快捷键：

- `⌘,` → 打开主窗口并切到设置 tab。
- `⌘1` → 打开主窗口并切到统计 tab。
- `⌘R` → 调用 `appState.refreshNow()`。

`AppDelegate` 只做一件事：`NSApp.setActivationPolicy(.accessory)` 让进程不出现在 Dock。

## 4. 全局状态：`AppState`

`@Observable @MainActor`，单例方式由 `CCBarApp` 持有并通过 `.environment` 注入。核心字段：

- `accounts: [MonitoredAccount]`：本轮发现的所有账号，按 `Provider.allCases` 顺序分组。每个账号带 `id: AccountID`（`"<provider>:<source key>"`，如 `codex:default` / `codex:imported:<id>` / `kimi:ccpm:work`）、`credential`（`codexOAuth` / `claudeOAuth` / `apiKey` / `ollamaCookie` / `unavailable`）、`identity`、`usageRoots` 与可选的 `mirrorsAccount`。
- `quota: [AccountID: AccountQuotaState]`：每个账号的 `snapshot` / `source`（`api` / `cache` / `cliFallback`）/ `error` / `refresh: QuotaRefreshState`（`lastSuccessAt`、`lastAttemptAt`、`backoffUntil`、`lastError`、`inFlight`、`source`）。镜像账号没有自己的条目，`quotaState(for:)` 会先解 `mirrorsAccount`。
- `serviceStatus: [Provider: ServiceStatus]`：只有 `ProviderDescriptor.statusPageURL != nil` 的 provider（Codex / Claude）会有值。
- `todayCost: [AccountID: Decimal]`：由 `UsageService.publishTotals()` 写入。
- `importedCodexAccounts`：手动导入账号的元数据列表，供设置页增删改；运行时账号仍从 `accounts` 读。
- UI 协调：`mainTab`、`shouldShowOnboarding`。
- 子系统：`usageService`、`scheduler`、`quotaCache` 内存副本、Claude CLI 兜底冷却 `claudeFallbackBackoffUntil`。

派生查询：`accounts(for:)`、`presentProviders`（有账号的 provider）、`visibleProviders`（再叠加设置开关）、`quotaState(for:)`、`monitorSnapshot(for provider:)`（同 provider 各账号每个窗口取剩余最低者，即 `QuotaSnapshot.mostConstrained`）、`latestVisibleSuccess` / `hasVisibleError`（header 状态点）。

关键方法：

- `bootstrap()`：只执行一次；按顺序读 quota 缓存 → 读今日历史 → 读导入账号元数据 → `UsageService.bootstrap` → 必要时弹 Keychain 引导 → `rediscover()` → 决定是否展示引导 → 启动 Scheduler → 并行触发首次 JSONL 扫描、服务状态拉取和一次 `refreshQuotas(reason: .periodic)`（异步不阻塞；60s 节流会跳过缓存仍新鲜的账号）。
- `rediscover()`：在后台跑 `AccountCatalog.discover(importedAccounts:)`，回到主线程 `apply`：同一 `AccountID` 的 `identity.fingerprint` 变化（例如 cc-switch 切了默认登录）时丢弃该账号的快照与缓存；不再存在的账号从 `quota` 与缓存中剔除。
- `refreshQuotas(reason:)`：先 `rediscover()`，再对「provider 已启用 · 非镜像 · 可查额度」的账号分批（每批 3 个）调用 `loadQuota`；`unavailable` 账号只把原因写进 `error`。结束后 `syncMirrors()`（给镜像账号记历史；把默认 Codex 的新 token 同步进被镜像的导入账号 Keychain）并打印摘要。
- `loadQuota(account:reason:)`：`beginRefresh` 做 in-flight / 429 退避 / 60s 节流检查 → `QuotaFetcher.fetch(account:)` → 成功则 `store`（写快照、缓存、历史，并把续期后的凭据写回 `accounts`；`source == .api` 时把新旧快照交给 `QuotaNotifier.shared.evaluate`），失败则 `markFailure`；默认 Claude 登录在手动刷新且无快照时走 CLI 兜底。
- `refreshNow()`：用户手动刷新；去重后依次跑额度刷新、JSONL 扫描、服务状态。
- `refreshServiceStatus()`：对可见且有状态页的 provider 并发拉取，失败保留旧值。
- `setOllamaCookie(_:profile:)`：写入 `OllamaCookieStore` 后清掉该账号的错误并立即刷新。
- 导入账号增删改排序方法保持原名（`upsertImportedCodexAccount` 等），内部落盘后 `reloadImportedCodexAccounts()` 触发一次 `rediscover()`。
- `applySettingsChange()`：设置项变化后立即把新间隔灌进 Scheduler。

## 5. 凭据读取

### 5.1 Codex

`CodexAuth.load()` 读 `~/.codex/auth.json`；`CodexAuth.load(from:)` 可读取任意 profile 的原生 `auth.json`。两者解析同一套 token / JWT 字段。

`CCPMProfileCatalog` 读取 `~/.ccpm/config.json`（也尊重 `CCPM_HOME`）的 `runtime` / `provider` / `auth_method` / `env`，缺失 `runtime` 的旧 profile 按 Claude 兼容；`runtime = codex` 的 OAuth profile 由 `AccountCatalog` 通过 `CodexAuth.load(from:)` 读取 `<profileDir>/auth.json`。Token 临期刷新只回写该 profile 文件，不覆盖默认 `~/.codex/auth.json`。

`CodexTokenRefresher.ensureFreshAccessToken`：当 JWT `exp` 剩余 < 300s 时 POST 到 OpenAI OAuth token 端点（grant_type=refresh_token，client_id 用 Codex CLI 公开 ID），按 `WriteBack` 写回默认文件、指定 ccpm profile 文件或手动导入账号 Keychain。

### 5.2 Claude

`ClaudeAuth.load()` 优先读 `~/.claude/.credentials.json`；不存在再调 `security find-generic-password -s "Claude Code-credentials" -w` 读 Keychain。邮箱兜底来自 `~/.claude.json` 顶层 `oauthAccount.emailAddress`。

`AccountCatalog` 对 `runtime = claude` 且 provider 为空或 `anthropic` 的 profile 调 `CCPMClaudeProfileStore.loadOAuthAccount(profile:identity:)`；只有 `auth_method = oauth` 的 profile 能查额度。profile 身份展示来自 `<profileDir>/.claude.json` 的 `oauthAccount`（`readIdentity(profileDir:)`）。macOS OAuth token 读取规则对齐 ccpm / Claude Code v2.1.56+：

- keychain service = `Claude Code-credentials-<sha256(abs(CLAUDE_CONFIG_DIR))[:8]>`，account 优先当前 macOS 用户名，兜底 `Claude Code` / `claude-code` / `default`。
- keychain 缺失时兜底读 `<profileDir>/.credentials.json`，兼容 Linux/旧版 file 格式。
- profile 专属 token 刷新后写回原 profile keychain service 或 profile credentials 文件，不写默认 `~/.claude` 槽位，也不调用 `ccpm set-default`。

`ClaudeTokenRefresher.ensureFreshAccessToken`：

- 端点 `https://platform.claude.com/v1/oauth/token`，client_id 用 Claude Code CLI 的公开 ID。
- 续期成功后按原存储位置（`.file` / `.keychain`）回写。Keychain 回写先用 `security find-generic-password` 读出原 JSON，merge token 字段后用 `security add-generic-password -U -s <service> -a $USER -w <json>` 整体覆盖，保留 `subscriptionType` 等附加字段。
- `expiresAt` 用毫秒时间戳与 CLI 对齐。

#### 与其他客户端共存的刷新策略

Claude 的 OAuth `refresh_token` 是 *一次性* 的：每次刷新服务端会旋转一个新值，旧值立即作废。用户机器上同时跑 Claude Desktop / Claude Code CLI / cc-switch / codexbar / cc-bar 时，谁先刷新成功，其他人手里的 `refresh_token` 都会变成 `invalid_grant`。为此 cc-bar 把自己当 *只读监控* 设计成"被动优先"：

1. **缩短 skew 让出主动权**：`refreshSkew` 由 300s 收紧到 30s，把 access_token 临期的主动刷新让给 CLI / Desktop。
2. **进程内串行 + 去重**：`Coordinator` actor 按 `ClaudeCredentialStorage.cacheKey` 维护 in-flight Task，菜单栏 / 悬浮窗 / Popover 三个入口几乎同时触发同一存储时合并成一次刷新，不会自家跟自家争抢；不同 ccpm profile 之间互不合并，避免误用别的 profile token。
3. **拿锁后先重读存储**：真正发请求前 `peekStored(source:)` 再读一次 credentials.json / Keychain；若已被别的客户端写入新鲜 access_token，直接采用，不发请求；若 refresh_token 已被旋转，至少用最新一份去发请求。
4. **文件 mtime 礼让窗口**：`~/.claude/.credentials.json` 在最近 `politeMtimeWindow=10s` 内被改过，认为别人刚完成刷新，sleep 1s 再重读一次。
5. **`invalid_grant` 软恢复**：拿到 `HTTP 400 invalid_grant` 不立即报错——sleep 1s 再重读，若 refresh_token 已被外部更新且 access_token 仍新鲜，静默采用、对 UI 报告成功。
6. **委托 CLI 兜底刷新**：软恢复仍失败时,`ClaudeDelegatedRefresh` 会尝试唤起本机 `claude` CLI(优先 `$CLAUDE_CLI_PATH` → 常见 PATH 位置 → Claude Desktop 内嵌的 `~/Library/Application Support/Claude/claude-code/<ver>/claude.app/Contents/MacOS/claude`),在最小 PTY 里跑一次 `/status`,让 CLI 用受信任的会话身份完成刷新并把新凭据写回 keychain / credentials.json;通过对存储指纹比对来判断是否成功。带 5 分钟冷却 + in-flight 去重,避免反复唤起。成功则静默使用新 token;CLI 找不到 / 仍失败时才升级成 `QuotaError.tokenRevoked`,给出"请运行 `claude` 重新登录"的友好提示。
   - 设计意图:在用户没主动操作 / 只在 Claude Desktop 中登录的常见场景下尽量自动恢复,而 Desktop 自身不会回写 CLI 的 `Claude Code-credentials` keychain 条目,所以需要 CLI 做这次代办。
   - **TCC 隔离**:为了避免 claude CLI 启动时扫描用户 home 目录触发"CCBar 想访问 文稿 / 桌面 / 相册..."这种归因到主体 App 的弹窗,实现做了两层防护:
     * **受控工作目录** `~/Library/Application Support/CCBar/ClaudeProbe/`:claude 启动时 cwd 设到这里,里面只有空的 `.claude/settings.local.json`(关掉 deep-link 注册),它扫不到任何用户项目结构。
     * **Watchdog 套娃** `CCBar.app/Contents/Helpers/CCBarClaudeWatchdog`:一个 ~120 行的小 Swift 二进制([Helpers/CCBarClaudeWatchdog/main.swift](../Helpers/CCBarClaudeWatchdog/main.swift)),只做 `posix_spawnp` claude + 信号转发 + 父进程死亡守护。cc-bar 通过 watchdog 启动 claude,macOS TCC 沿进程链上溯时看到的是独立签名的 watchdog 而非主体 App,任何潜在的权限弹窗都归因到 helper,不污染 cc-bar 的权限画像(对齐 CodexBar 的 `CodexBarClaudeWatchdog` 做法)。
     * 构建方式:CCBar target 加了一个 `Embed CCBarClaudeWatchdog` 的 Shell Script Build Phase(在 Resources 之后),用 `swiftc` 编译 main.swift 并 codesign 到 `Contents/Helpers/CCBarClaudeWatchdog`。Debug 跑(尤其 Xcode Run 但 bundle 里没 helper)会降级到直接起 claude,可能弹一次权限框,可以接受。

> Codex 那边目前还是原始策略（`refreshSkew=300`，无 Coordinator / 软恢复 / 委托刷新），后续按需对齐。

### 5.3 ccpm profile → 账号映射（`AccountCatalog`）

`AccountCatalog.discover(importedAccounts:)` 在后台线程把四个来源合成一份 `[MonitoredAccount]`：默认 Codex、默认 Claude（凭据读不到时仍产出账号，凭据为 `.unavailable(reason:)`，这样 Popover 能显示原因而不是让 provider 消失）、勾选显示的导入 Codex 账号、ccpm profiles。ccpm 映射：

| runtime | provider | auth_method | credential | usageRoots |
|---|---|---|---|---|
| codex | — | oauth | `.codexOAuth(account, writeBack: .codexAuthJSONAt(path))` | `<dir>/sessions`, `<dir>/archived_sessions` |
| codex | — | 其他 | `.unavailable` | 同上 |
| claude | 缺省 / anthropic | oauth | `.claudeOAuth(account, storage)` | `<dir>/projects` |
| claude | anthropic | 其他 | `.unavailable` | `<dir>/projects` |
| claude | kimi / glm | api_key | `.apiKey(key, baseURL)`，key 来自 `CCPMKeystore`，baseURL 取 `env.ANTHROPIC_BASE_URL` 或 descriptor 默认；keystore 无 key 时 `.unavailable` | `<dir>/projects` |
| claude | ollama | api_key | `.ollamaCookie(cookieHeader?, baseURL)`，cookie 来自 `OllamaCookieStore`（可为空） | `<dir>/projects` |
| 其他 provider 值 | | | 忽略并打日志 | |

ccpm profile 顺序：默认 profile 优先，其次 `last_used` 倒序，再按名字。Codex 镜像规则不变：导入账号或 ccpm Codex profile 与默认登录同身份（`chatgpt_account_id` + `chatgpt_user_id`）时 `mirrorsAccount = codex:default`；ccpm Codex profile 与某个可见导入账号同身份时镜像该导入账号。

ccpm fork 侧：`ccpm add <name> --provider kimi|glm|ollama` 写入 `provider` 字段与默认 `ANTHROPIC_BASE_URL`（Kimi `https://api.kimi.com/coding/`、GLM `https://open.bigmodel.cn/api/anthropic`、Ollama `https://ollama.com`），`run` / `use` / `set-default` 启动时把 keystore 的 key 注入为 `ANTHROPIC_AUTH_TOKEN`；Anthropic profile 仍用 `ANTHROPIC_API_KEY`。cc-bar 不解析 URL 猜 provider。

### 5.4 ccpm keystore（`CCPMKeystore`）

ccpm 用 go-keyring 把 API key 存成 Keychain 通用密码：service `ccpm`，account = profile 名。cc-bar 用 `security find-generic-password -s ccpm -a <profile> -w` 读出，再按 go-keyring 前缀解码：`go-keyring-base64:` → base64，`go-keyring-encoded:` → hex，无前缀原样返回。条目由 `security` CLI 创建，同一 CLI 读取不会触发授权弹窗。

### 5.5 Ollama Cloud Cookie（`OllamaCookieStore`）

ollama.com 没有额度 API，只能带登录 Cookie 抓设置页。用户在「设置 → ccpm 账号」为 Ollama profile 粘贴 `Cookie:` 头（可带 `Cookie:` 前缀，会被剥掉），存为 cc-bar 自己的 Keychain 通用密码（service `com.cc-bar.ollama.cookie`，account = profile 名，`SecItem` 读写不弹窗）。这是「不做浏览器 Cookie 自动导入」原则下的手动例外：cc-bar 不读浏览器数据库。

## 6. 额度查询

### 6.1 接口

| Provider | 请求 | 关键 Header | 客户端 |
|---|---|---|---|
| Codex | `GET https://chatgpt.com/backend-api/wham/usage` | `Authorization: Bearer …`、`ChatGPT-Account-Id`、`User-Agent: codex-cli` | `CodexQuotaClient` |
| Claude | `GET https://api.anthropic.com/api/oauth/usage` | `Authorization: Bearer …`、`anthropic-beta: oauth-2025-04-20`、`User-Agent: claude-code/2.1.0` | `ClaudeQuotaClient` |
| Kimi Code | `GET {scheme+host of ANTHROPIC_BASE_URL}/coding/v1/usages` | `Authorization: Bearer <api key>` | `KimiQuotaClient` |
| GLM | `GET {scheme+host of ANTHROPIC_BASE_URL}/api/monitor/usage/quota/limit` | `Authorization: Bearer <api key>` | `GLMQuotaClient` |
| Ollama Cloud | `GET https://ollama.com/settings` | `Cookie: <用户粘贴>`、浏览器 UA | `OllamaCloudQuotaClient` |

所有响应都映射到统一的 `QuotaSnapshot { provider, primary, secondary, extra, planType?, fetchedAt }`，每个窗口是 `QuotaWindow { kind, usedPercent, resetsAt?, windowSeconds?, detail? }`，`kind ∈ fiveHour / weekly / monthly / weeklyOpus / weeklySonnet / mcp / extraUsage`，`remainingPercent = 100 − usedPercent`。主副窗口由各客户端按 `ProviderDescriptor.primaryKind / secondaryKind` 装配；菜单栏 / HUD 的「5H/WK」切换只是主副互换，标签取 `kind.shortLabel`（Ollama 显示 MO / WK）；Popover 卡片列出 `allWindows` 全部窗口。

各客户端的映射：

- **Codex**：`rate_limit.primary_window` / `secondary_window` 在接口里只是位置，真实周期看 `limit_window_seconds`：≤6 小时 → `fiveHour`，6～8 天 → `weekly`，>8 天 → `monthly`，缺失时按位置兜底（primary → `fiveHour`，secondary → `weekly`）；解析后按 `windowSeconds` 升序排，session 窗口永远在前。Pro 20x 只返回 `primary_window`（`limit_window_seconds = 604800`）且 `secondary_window = null`，因此该账号只有一个 `weekly` 窗口：Popover 卡片只画一段 Weekly，菜单栏 / HUD 的主窗口就是周窗（标签 `WK`），不会再把周窗误标成 5H。
- **Claude**：`five_hour` / `seven_day` → 主副；`seven_day_opus` / `seven_day_sonnet` 进 `extra`；`extra_usage { is_enabled, monthly_limit, used_credits, utilization, currency }` 在 `is_enabled == true` 且 `monthly_limit > 0` 时映射为 `extra` 的 `extraUsage` 窗（金额按分计，÷100 与 CodexBar 一致；`usedPercent` 优先取 `utilization`，否则 `used / limit`；`detail = "$12.34 / $2000.00"`，货币符号按 `currency`，无 reset）。`parse(data:now:)` 独立于 `fetch`，供自检直接调用。
- **Kimi Code**：`limits[0]`（`window{duration,timeUnit}` + `detail{limit,used,remaining,resetTime}`）→ `fiveHour`，`detail = "139/200 requests"`；`usage{limit,used,remaining,resetTime}` → `weekly`（周请求数配额）。数值字段可能是字符串或数字，统一走 `QuotaJSON`。
- **GLM**：`data.limits[]` 中 `TOKENS_LIMIT` / `CREDIT_LIMIT` 按窗口长度排序，最短为主、最长为副（300 分钟 → `fiveHour`，7 天 → `weekly`）；`TIME_LIMIT` 作为 `extra` 的 `mcp` 窗（`unit=5,number=1` 视为月窗）。百分比优先用 `usage` 与 `currentValue / remaining` 计算，否则用 `percentage`；5 小时窗的 `nextResetTime` 若超过当前时间 5 小时零 1 分钟则丢弃。`planName` 等字段 → `planType`；`success == false` 且 `code == 401` 映射为 `QuotaError.http(401)`。
- **Ollama Cloud**：抓 HTML，`Included usage` / `Cloud Usage` 后的 badge 为 plan；`Monthly usage` 段内 `$X of $Y used` → `monthly`（`detail = "$X of $Y"`），`Weekly usage` 段内 `N% used` 或进度条 `width: N%` → `weekly`，旧版 `Session usage / Hourly usage` → `extra` 的 `fiveHour`；`data-time="…"` 为 reset。跟随重定向落到 `/signin` 或页面含登录表单 → `QuotaError.http(401)`（提示重新粘贴 Cookie）。

分发入口是 `QuotaFetcher.fetch(account:)`：按 `credential` 分支，`codexOAuth` / `claudeOAuth` 先走对应 `TokenRefresher` 续期再请求，并把续期后的凭据随结果返回；`apiKey` 按 provider 选 Kimi / GLM 客户端；`ollamaCookie` 缺 cookie 时直接返回 `QuotaError.missingCookie`。

### 6.2 调用策略

- 启动先读 `quota-cache.json` 灌进 `AppState.quota` 让 UI 立刻有数，随后 `bootstrap` 末尾立即发一次 `refreshQuotas(reason: .periodic)`；缓存里 `lastSuccessAt` 距今不足 60s 的账号被节流跳过，其余账号马上拉一次。
- 周期循环按设置间隔触发（默认 2 分钟）；每个账号独立判断：上次成功 < 60s 时跳过。
- 收到 429 后该账号进入 10 分钟退避，期间所有触发短路；其他账号不受影响。
- 手动刷新绕过 60s 节流，但仍遵守 429 退避。
- 同时最多 3 个账号并发；镜像账号不发请求。
- 401 / 403 不会自动停止循环（保持简单），但错误会显示在 Popover（Kimi / GLM 提示 key 无效，Ollama 提示重新粘贴 Cookie）。
- 网络/解析失败保留旧快照，错误写入 `lastError`，下一 tick 重试。

### 6.3 Claude CLI 兜底

`ClaudeCLIFallbackQuotaClient` 仅对默认 Claude 登录（`claude:default`）生效：`refreshNow` 触发的 API 失败 **且** 该账号没有任何快照时启动，自身有 10 分钟独立冷却；ccpm Claude profile 不走兜底：

- 候选可执行：`/opt/homebrew/bin/claude` → `/usr/local/bin/claude` → `/usr/bin/claude` → `env claude`。
- 用 `/usr/bin/script -q /dev/null <claude>` 包一层伪 PTY 拿到 ANSI 输出；失败再裸跑一次直接执行。
- 通过 stdin 写入 `/usage\n\n/status\n/exit\n` 驱动 CLI。
- 输出 strip ANSI，按 `Current session` / `Current week (all models)` / `Current week (Sonnet only)` / `Current week (Opus)` 标签抓百分比与 `Resets …` 文本。
- 错误关键词识别：`rate_limit_error` / `authentication_error` / `failed to load usage data`，转成对应 `QuotaError`。

CLI 兜底拿到的 snapshot 用 `QuotaSnapshotSource.cliFallback` 标记，仅用于救急展示。

### 6.4 持久化

`QuotaCache` 写 `~/Library/Application Support/CCBar/quota-cache.json`（v2），结构 `{ version: 2, records: [AccountID.raw: Record] }`，每条记录含 snapshot、source、updatedAt；镜像账号不写缓存。旧版本文件整体丢弃。

这份文件现在是**跨工具契约**：ccpm 的 `statusline` 子命令在 Claude Code 没有推送 `rate_limits`（API key profile，即 Kimi / GLM / Ollama / Anthropic api_key）时会读取它，按 `<provider>:ccpm:<profile>` 取记录（Anthropic profile 的 provider 写作 `claude`），只用 `primary` / `secondary`，`updatedAt` / `resetsAt` 是 Swift `JSONEncoder` 默认的 Apple 参考时间秒数（+978307200 为 Unix），记录超过 30 分钟即忽略。改动字段或时间编码时必须升 `version`，并同步 ccpm 的 `cmd/statusline_ccbar.go`。

`QuotaHistoryStore` 写 `~/Library/Application Support/CCBar/quota-history-today.json`，只保存本地当天数据：

- `lastSamples`：每个账号最近一次成功采样的 5H 剩余整数百分比，作为下一次对比基准。
- `events`：只有 5H 剩余整数百分比发生变化时才新增事件，字段包含账号 key、应用、账号类型、采样时间、变动前 / 后剩余、delta 和 5H 重置时间。
- 启动和每次写入都会按本地 `Calendar.current.startOfDay` 清理非当天数据。
- 每个账号以 `AccountID.raw` 为 key（v2，样本与事件带 `provider`）；跟踪的窗口是 `snapshot.timelineWindow`：有 `fiveHour` 用它，否则（Ollama Cloud）用主窗口。镜像账号在被镜像账号来源为 API 成功快照时同步记录。

### 6.5 服务状态（`ServiceStatusClient`）

OpenAI / Anthropic 各自的 Statuspage.io 公开接口,无需鉴权,用于在 Popover 中显示一个状态圆点：

| 服务 | 端点 |
|---|---|
| OpenAI | `https://status.openai.com/api/v2/status.json` |
| Anthropic | `https://status.claude.com/api/v2/status.json` |

响应中 `status.indicator` 取值 `none / minor / major / critical / maintenance`，未识别值归并为 `unknown`。`ServiceStatusClient.fetch` 解析为 `ServiceStatus { indicator, description, updatedAt, fetchedAt }`，10s 超时。

调用策略：

- `AppState.refreshServiceStatus()` 对可见且 `ProviderDescriptor.statusPageURL != nil` 的 provider（目前 Codex / Claude）并发拉取，单边失败不影响另一边；网络/解析失败保留上一份快照，不清空。Kimi / GLM / Ollama 没有状态页，不显示圆点。
- 由 `Scheduler` 固定 5 分钟一次驱动；启动后立即拉一次；`refreshNow()` 也会顺带刷新。
- 仅做展示，不缓存到磁盘。

### 6.6 消耗节奏（`QuotaPace`）

`QuotaPace.compute(window:now:)` 把已用比例与窗口已过去比例做差：`elapsed = 1 − (resetsAt − now) / windowSeconds`，`deltaPercent = round((used − elapsed) × 100)`，正值表示超前于匀速消耗。`windowSeconds` 依次取窗口自带值 → `kind.defaultSeconds`（5H = 18000，周 = 604800）→ 月窗按 reset 反推一个自然月。窗口过去不足 3% 时返回 `nil`（数据太少）。超前时按当前速率外推耗尽时刻 `runsOutAt`，只在早于 reset 时给出。Popover 卡片在每个窗口段下方显示这一行；菜单栏与 HUD 不显示。

### 6.7 额度通知（`QuotaNotifier`）

`@MainActor` 单例，只被 `AppState.store` 在 `source == .api` 时调用（缓存与 CLI 兜底快照不触发）。设置 `quotaNotifications` 关闭时直接返回。对 `next.allWindows` 每个窗口按 `kind` 找到旧快照里的同类窗口后判定三类事件：

| 事件 | 条件 | 正文（英文口径） |
|---|---|---|
| reset | `kind ∈ fiveHour / weekly / monthly`，新 `resetsAt` 比旧值晚 > 1 小时，且剩余回升 ≥ 30 个百分点；同时清掉该窗口的 low / exhausted 记忆 | `WK quota reset · 100% left` |
| exhausted | 剩余 ≤ 0 且旧值 > 0 | `5H quota exhausted · resets in 2h 13m` |
| low | 剩余 ≤ 20 且旧值 > 20（旧快照缺失时视旧值为 100） | `5H 18% left · resets in 1h 05m` |

标题为 `<displayName> · <shortTitle>`（隐私模式下用「Account N」）。去重键 `account|kind|event` 存内存，通知标识符 `ccbar.quota.<key>` 固定，重复投递会替换而不是堆叠。授权走 `UNUserNotificationCenter.requestAuthorization([.alert, .sound])`，第一次真正要发送时才申请，结果缓存在进程内；被拒绝时静默跳过。

## 7. 本地 JSONL 扫描

### 7.1 Claude（`ClaudeJSONLScanner`）

- 入口是账号的 `usageRoots`：默认登录 `~/.claude/projects`，ccpm Claude 运行时 profile（含 Kimi / GLM / Ollama）`<profileDir>/projects`；`scan(roots:accountId:provider:previous:seenMessageIds:)` 把解析出的条目打上账号 id 与 provider。
- 每条 `type=assistant` 行解析 `message.id` / `message.model` / `message.usage`（`input_tokens` 不含 cache_read）/ `stop_reason`。
- 本批次内按 `message.id` 取唯一，优先选 `stop_reason != nil` 或更高 output_tokens 的一条；最后与全局 `seen` 集合比对，避免 sidechain / subagent 文件中重复计数。
- 全局 seen 列表持久化在 `scan-state.json`，上限 20000，超出截尾。

### 7.2 Codex（`CodexJSONLScanner`）

- 入口是账号的 `usageRoots`：默认登录 `~/.codex/sessions` + `~/.codex/archived_sessions`，ccpm Codex profile `<profileDir>/sessions` + `<profileDir>/archived_sessions`；`scan(roots:accountId:previous:)`。手动导入的 Codex 账号没有本地日志。
- `turn_context` 行更新当前模型（写入 `ScanFileState.lastModel`）。
- `event_msg` 且 `payload.type == "token_count"` 行，从 `payload.info.last_token_usage` 直接累计（不是累计 delta），`info == nil` 跳过。
- `billable_input = input_tokens − cached_input_tokens`（Codex 的 `input_tokens` 含 cache_read）。

### 7.3 增量与持久化（`ScanCache`）

- 每个文件维护 `ScanFileState { mtime, offset, lastModel? }`。
- 调度逻辑：`mtime == prev && offset == size` → 跳过；`offset > size` → 文件被截断，归零重扫（去重靠 seen 集合）；否则从 `offset` 处续读到末尾。
- 已不存在的文件 watermark 在每次扫描末尾清理。
- 顶层结构 `ScanState { version, pricingFingerprint, files, claudeSeenMessageIds }`（v5）：所有账号的文件 watermark 共用一张按绝对路径索引的 `files` 表，扫描结束后只保留任一根目录下仍存在的文件。`UsageRollupPayload { version, pricingFingerprint, buckets, updatedAt }` 同步用 v5。
- **失效条件有二**：`version` 管「结构变更」（字段增减导致解码不兼容时 bump）；`pricingFingerprint`（`Pricing.fingerprint`，价格表内容的 SHA-256）管「价格变更」。load 时任一与当前值不一致即整份丢弃，触发全量重扫重算历史桶。改价格表（新增模型、改价、修正数值）后无需手动 bump 版本号——指纹自动失效，避免「改了价却忘了重算」导致历史 cost 不一致。

### 7.4 聚合（`UsageAggregator`）

- `@Observable @MainActor`，内存 `[BucketKey: UsageBucket]`，BucketKey = (day, accountId, model)；桶里另带 `provider`。
- `ingest(entries)` 累加 token 与 cost；`snapshot()` 返回数组用于落盘；`todayCost(accountId:)` / `totals(provider:from:to:)` / `totals(accountId:from:to:)` 给 UI 用。
- 由于是 `@Observable`，Popover 和统计 tab 在 body 读 `aggregator.totals(...)` 时自动建立依赖，新扫描完写回 buckets 后 UI 自动刷新。
- **Token 展示口径**：`UsageTotals.inputWithCacheTokens = input + cache_read + cache_creation`，`totalTokens = inputWithCacheTokens + output`。Stats 页的"总令牌 / By service tokens / By model 入"统一使用此口径，与 cc-switch / ccusage 对齐；其中 Claude 的 `input_tokens` 本身不含 cache_read，Codex 的 `inputTokens` 在解析时已扣过 `cached_input_tokens`，因此三项相加不会重叠。

### 7.5 价格（`Pricing`）

- 表硬编码于 `Pricing.swift`，命中不到的 model cost = 0，token 仍记录。Kimi / GLM / Ollama 的模型不在表里，对应 provider 的 `supportsCost == false`，UI 只显示 token。
- 归一化：剥 `openai/` 前缀；Vertex 风格 `name@YYYYMMDD` 截断 `@` 前；Anthropic 风格 `-YYYY-MM-DD` 或 `-YYYYMMDD` 后缀剥掉；最后 `lowercased()`。
- 金额用 `Decimal`（`Foundation.Decimal`），单位 USD / 百万 token。
- `Pricing.fingerprint`：价格表内容的 SHA-256，写进扫描状态 / 汇总缓存；表一变指纹即变，缓存自动失效触发全量重扫重算（见 §11 持久化失效条件）。

### 7.6 协调（`UsageService`）

- `bootstrap` 在 AppState 启动时读取 `usage-rollup.json` 灌进 aggregator，立即对外发布今日 cost。
- `scanNow()` 防重入：从 `ScanCache` 读旧 watermark，对 `appState.accounts` 中 `usageRoots` 非空的账号用 TaskGroup 并行扫描（最多 4 个），合并条目、文件状态、存活路径与 seen 集合后 `ingest`，写 `scan-state.json` 与 `usage-rollup.json`，更新 `lastScanAt` 并按账号 publish today cost（`AppState.todayCost`）。

## 8. 调度（`Scheduler`）

`@MainActor`，持有 AppState 弱引用，三条独立 `Task` 循环：

- **额度循环**：`quotaInterval` 秒触发一次 `appState.refreshQuotas(reason: .periodic)`。设置项可选 `1 / 2 / 3 / 5 / 10` 分钟，默认 2 分钟；`Scheduler` 仍保留对 `nil` / 0 的兜底，不启动循环。
- **用量循环**：`usageInterval` 秒触发一次 `appState.usageService.scanNow()`。
- **服务状态循环**：固定 5 分钟触发一次 `appState.refreshServiceStatus()`，与额度/用量解耦（statuspage 变化慢，无需跟随用户的额度刷新间隔）。

`setQuotaInterval` / `setUsageInterval` 在间隔变化时取消旧 task 并按新参数重启，对应设置变更的实时生效。

## 9. UI 层

### 9.1 菜单栏 label

`MenuBarLabel` 用 SwiftUI 包一层 `Image(nsImage:)`，真正画图在 `MenuBarBadgeImage.make`：

- 段间距 9pt。

- Logo 从 `Resources/Logos/<provider>.svg` 加载，缓存在 `NSCache`；加载失败时画 `ProviderDescriptor.fallbackGlyph`。

- 用户都关闭时返回单 logo 占位，避免菜单栏空白。

### 9.2 Popover (`PopoverRootView`)

- 宽 340pt；header（标题 + 副标题 + 状态点 + 主副窗口切换 + 刷新/统计/设置/退出）+ 每个可见 provider 一个 `ProviderSection`，中间 Divider；内容区包在 ScrollView 中并按卡片数与每张卡的窗口数估算高度（卡片基础 78pt + 每窗口 58pt + 节奏行 16pt + 本地用量段 70pt + 操作行 20pt + 错误行 20pt），最高约 680pt 后滚动。
- `ProviderSection(provider:)`：每个账号一张 `ServiceBlockView` 卡片；账号数 > 1 时先渲染 `ServiceAccountsSectionHeader`。

## 13. 已知技术债 / 持续关注

- **Claude CLI 兜底依赖外部进程**：用户没装 CLI 时会失败，目前只在 API 失败且无缓存的手动刷新触发，影响面有限。
- **价格表手维护**：模型更新需要同步 `Pricing.swift`；改表后由 `Pricing.fingerprint` 指纹自动失效缓存触发重扫，无需手动 bump 版本号。
- **seen ID 上限 20000**：极端长时间使用 + 大量 sidechain 引用可能导致环形丢失；目前足以覆盖正常使用。
- **没有自动更新通道**：发布要手动出包；后续可接 Sparkle。
- **Ollama Cloud 靠 HTML 解析**：`ollama.com/settings` 改版即失效；`scripts/selfcheck.sh` 固定了新旧两版页面样例，改版后先更新样例再改解析器。
- **Kimi / GLM 接口非公开**：控制台接口字段可能变化，解析对字符串 / 数字容错但不保证语义不变。

## 14. 导入账号（其他 Codex 账号）

用户可在设置页手动粘贴 `~/.codex/auth.json` 内容，为 cc-bar 添加任意多个 Codex 副账号（仅查看配额，不影响 CLI 的当前登录状态）。

### 14.1 设计原则

- **凭据与默认账号解耦**：默认账号始终来自实时读取 `~/.codex/auth.json`（cc-switch 切号也跟着变）；导入账号是独立副本，各自维护 token，绝不写回 `~/.codex/auth.json`。若导入账号与当前默认账号身份相同，额度展示与刷新状态复用默认账号快照，不再读取导入 token 或重复请求官方接口；同时把当前默认账号 token 同步到该导入账号的 Keychain 副本，修复导入凭据长期未更新导致的后续刷新失败。
- **允许重复**：同一账号 ID 可以同时出现在默认槽和导入列表，语义不同（「当前 CLI 账号」vs「我关注的账号」），不强制去重；重复条目仅作为展示条目保留，刷新时镜像默认账号数据。
- **同 ID 覆盖**：再次粘贴相同账号时静默覆盖 token（保留 alias / visible 设置），避免悬空旧 token。
- **Team 账号区分用户**：账号身份用 `{chatgpt_account_id}:{chatgpt_user_id}` 复合键，同一 Team account 下不同 user 视为独立条目；缺失 `chatgpt_user_id` 时退化为单段 `chatgpt_account_id`（老数据兼容）。HTTP 请求里的 `ChatGPT-Account-Id` header 仍只取前半段。

### 14.2 存储

| 数据 | 位置 | 说明 |
|---|---|---|
| 元数据（id / alias / email / planType / visibleInPopover / addedAt） | `Application Support/CCBar/imported_codex_accounts.json` | 原子写，JSON version = 1。`id` 为 `{account_id}:{user_id}` 复合键 |
| Token 三件套（access / refresh / id） | macOS Keychain，`service = com.cc-bar.codex.imported`，`account = ImportedCodexAccount.id`（复合键） | SecItem 直接读写，不弹用户授权 |
| 额度快照缓存 | `quota-cache.json` 的 `importedCodex` 字段（`[String: QuotaCacheRecord]`） | 重启时立即显示上次数据 |

### 14.3 Token 续期回写隔离

`CodexTokenRefresher.ensureFreshAccessToken` 新增 `writeBack: WriteBack` 参数：
- `.codexAuthJSON`（默认）：续期后覆盖写回 `~/.codex/auth.json`，与现有行为一致。
- `.importedAccount(id:)`：续期后仅更新 Keychain 对应条目，不碰 `~/.codex/auth.json`。

### 14.4 刷新调度

导入账号在 `AccountCatalog.discover` 中变成 `codex:imported:<id>` 账号（仅 `visibleInPopover = true` 的），和其它账号一起进入 `AppState.refreshQuotas` 的分批并发（每批最多 3 个）：
- 每个账号独立维护 `AccountQuotaState.refresh`（backoff / inFlight / lastSuccessAt），互不影响。
- 若导入账号与当前默认 Codex 账号匹配（优先 `{chatgpt_account_id}:{chatgpt_user_id}`，任一侧缺 user_id 时退回纯 account_id），`mirrorsAccount = codex:default`：不读取导入账号 Keychain token、不续期、不请求 `wham/usage`，`quotaState(for:)` 直接返回默认账号的状态；`syncMirrors()` 在默认账号有 `access_token` 时把它同步写入导入账号 Keychain，供该账号后续不再是默认账号时独立刷新。

### 14.5 排序

- 列表顺序即 `imported_codex_accounts.json` 中 `accounts` 数组顺序,Popover「其他账号」按相同顺序展示。
- 设置页支持拖动排序:每行 `.draggable(account.id)` + `.dropDestination(for: String.self)`,放下后调 `AppState.reorderImportedCodexAccounts(orderedIds:)` 写回 `ImportedCodexStore.saveAll`,再触发 `reloadImportedCodexAccounts` 同步运行时。
- 新增的账号追加到列表末尾;`reorderImportedCodexAccounts` 对未在传入 ids 中的条目自动追加到末尾,避免丢失。

### 14.6 Paste 解析（ImportedCodexPaste）

支持两种粘贴形态：
1. **完整 auth.json**（`{OPENAI_API_KEY, tokens: {...}, ...}`）
2. **裸 tokens 子对象**（`{access_token, refresh_token, ...}`）

解析优先级：`tokens.account_id` → `access_token` JWT payload → `id_token` JWT payload。email / planType 从 `id_token` 解，缺 id_token 时再从 `access_token` 的 JWT 里找。

## 15. ccpm profiles 与第三方 provider

cc-bar 只读发现 ccpm 的所有 profile 并映射为账号（详见 §5.3）：

- Profile 发现：`CCPMProfileCatalog` 读取 `~/.ccpm/config.json`，保留 name / dir / runtime / auth_method / provider / env / default_profile / last_used；旧 profile 缺失 runtime 时按 Claude 兼容，缺失 provider 时按 Anthropic。
- Codex 凭据：直接读取 `<profileDir>/auth.json`，不复制到 cc-bar Keychain；与主账号或手动导入账号身份相同时复用其配额状态，避免重复请求。
- Claude 凭据：OAuth profile 优先读 profile 专属 macOS Keychain service `Claude Code-credentials-<sha256(abs(profileDir))[:8]>`；若不存在，兜底 `<profileDir>/.credentials.json`。
- Kimi / GLM：API key 来自 ccpm keystore（§5.4），额度接口 host 跟随 profile 的 `ANTHROPIC_BASE_URL`。
- Ollama Cloud：Cookie 头来自 cc-bar Keychain（§5.5）。
- 刷新调度：所有可查额度的账号按 `AccountID` 分批并发刷新，每批最多 3 个；每个账号使用独立的刷新状态、错误、缓存与 429 退避。
- Token 回写：Codex 只回写自己的 `auth.json`；Claude 通过 `ClaudeCredentialStorage` 只回写 profile 自己的 keychain service / credentials 文件；API key / Cookie 账号无回写。
- 本地用量：ccpm profile 的 `<dir>/projects` 或 `<dir>/sessions` 作为该账号的扫描根目录，费用 / token 归属到该账号。
- 缓存与历史：`quota-cache.json.records[<AccountID>]` 与 `quota-history-today.json` 按账号 key 记录。
- UI：ccpm 账号进入所在 provider 的分区，与默认账号使用同一张卡片；Settings 的「ccpm 账号」列表与 Stats Timeline 均按账号展示。
