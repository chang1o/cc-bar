## 1. 背景与目标

cc-bar 已有本地用量统计（主窗口「统计」tab：KPI、每日用量柱状图、按服务、按模型、Timeline）。对照 cc-switch 的「使用统计」页，当前缺少：

1. **Token 结构细分**：新增输入 / 输出 / 缓存写入 / 缓存命中四项、缓存命中率、总请求数。目前只展示合计 tokens 和成本。
2. **模型筛选**：目前只能按服务（Codex / Claude）过滤，不能按模型过滤。
3. **使用趋势图**：目前只有按天的成本柱状图，没有 token 结构随时间变化的趋势图，当天范围也没有小时粒度。
4. **对话（会话）维度**：完全没有。这是本次的核心新功能——展示**每个对话**的 token 消耗（含四项细分）与费用。

总目标：把 cc-switch 用量统计中适用于 cc-bar 架构的部分迁移过来，并新增对话明细能力；交互与视觉延续 cc-bar 现有原生风格（不照抄 cc-switch 的 Web 风格）。

## 2. 关键前提：数据来源差异（决定能做什么）

cc-switch 的用量数据来自它内置的**本地代理**（拦截每一次 API 请求记账，含供应商、状态码、延迟）。cc-bar 没有代理，数据来自**扫描本地 JSONL 会话日志**：

- Claude：`~/.claude/projects/**/*.jsonl`，每行含 `sessionId` / `cwd` / `gitBranch` / `message.usage`。
- Codex：`~/.codex/sessions/**/*.jsonl`（+ archived），每文件一个会话，`session_meta` 含会话 id / cwd，`token_count` 事件含每次调用 token。

由此决定的能力边界（详见 §6 不做清单）：**做不了**供应商维度、HTTP 状态码 / 成功率、延迟；**恰好很适合做**对话维度（JSONL 天然按会话组织）。

## 3. 术语与统计口径

| 术语 | 口径 | 备注 |
|---|---|---|
| 新增输入 input | 不含缓存的计费输入 token | Claude 的 `input_tokens` 本身不含缓存；Codex 为 `input_tokens − cached_input_tokens − cache_write_tokens`（若本地日志提供 cache-write 字段） |
| 输出 output | `output_tokens` | |
| 缓存写入 cacheCreation | Claude `cache_creation_input_tokens`；Codex 的 `cache_write_tokens`（顶层或 token details） | GPT-5.6 按官方 cache-write 价计费；当前 Codex 本地日志缺该字段时按 0，不推测，UI 须显示 N/A 并说明是本地日志限制 |
| 缓存命中 cacheRead | Claude `cache_read_input_tokens`；Codex `cached_input_tokens` | |
| 真实消耗 Tokens | input + output + cacheCreation + cacheRead | 即现有 `UsageTotals.totalTokens`，与 cc-switch「真实消耗」一致 |
| 缓存命中率 | cacheRead ÷ (input + cacheCreation + cacheRead) | 分母不含 output；对齐 cc-switch |
| 请求数 | Claude：去重后的 assistant 消息条数；Codex：`token_count` 事件条数 | 与 cc-switch 的「代理请求数」口径接近但不完全等价，文档与 tooltip 不写「API 请求」，统一叫「请求数」 |
| 成本 | 按 `Pricing.swift` 价格表四项分别计费求和 | 命中不到价格的模型 cost=0、token 照记（现状） |
| 对话（会话） | Claude：一个 `sessionId`；Codex：一个 rollout 文件（`session_meta.id`） | Claude 的 subagent / sidechain 会形成独立 sessionId，见 §7 待确认项 |

## 4. 功能需求

优先级：P0 必做；P1 建议做（本期做完最好）；P2 可延后。

### F1 总览指标增强（P0）

位置：统计 tab · Overview 视图，改造现有 KPI 区。

- Hero 主卡：**真实消耗 Tokens** 大数字（千分位 + 紧凑近似值，如 `≈ 7217.24 万`）、**请求数**、**总成本**。
- 四项细分卡：新增输入 / 输出 / 缓存写入 / 缓存命中（紧凑格式）。
- **缓存命中率**：百分比 + 水平进度条。
- 缓存写入的 N/A 规则：筛选为 Codex 且所选本地日志没有 `cache_write_tokens` 时显示 `N/A` + tooltip「当前 Codex 本地日志未提供缓存写入 token」；筛选为全部且含该类 Codex 数据时正常显示数值 + tooltip「Codex 缓存写入缺少本地日志字段，数值可能偏低」。
- 保留现有「相对上一同长度区间」的 delta 百分比能力（cc-switch 没有，是 cc-bar 的优势项），至少保留在总成本 / 真实消耗上。
- 所有指标随服务 / 模型 / 时间范围筛选联动，且与下方趋势图、明细表数字**同源一致**（同一次聚合口径）。

### F2 模型筛选（P0）

- 顶部筛选区新增「模型」下拉：选项 = 当前服务筛选 + 时间范围内**实际有数据**的模型（归一化后的模型名），附「全部模型」项。
- 级联规则（对齐 cc-switch）：切换服务筛选时清空模型筛选；当前选中的模型因改时间范围掉出选项列表时，选项中补回该模型，保证用户看得见并能主动清除。
- 模型筛选作用于：总览指标、趋势图、按模型明细、对话明细列表。

### F3 使用趋势图（P0）

- 新增「使用趋势」面板（保留现有每日成本柱状图，两者并存）。
- 四条 token 序列的面积图：新增输入 / 输出 / 缓存写入 / 缓存命中；序列颜色固定并配图例。
- 粒度：时间范围 ≤ 1 天按**小时**，否则按**天**。
- 成本序列：由于 SwiftUI Charts 不支持双 Y 轴，用「Tokens / 成本」segmented 切换指标（默认 Tokens），不学 cc-switch 的同图双轴。
- 悬浮：沿用现有每日图的 `chartXSelection` 悬浮模式，浮层列出该时点各序列值（token 紧凑格式、成本 $）。
- 空状态：`No data · 无数据`。

### F4 按模型明细增强（P1）

- 现有 byModelPanel 扩为完整表：模型 · 请求数 · 输入 · 输出 · 缓存写入 · 缓存命中 · 总 tokens · 成本；默认按成本降序。
- 未命中价格表的模型在成本列显示 `未定价`（次要色），不显示 $0.00 误导。数据层已就绪：`Pricing.hasPrice(model:)` 现已同时覆盖本地表 / 阶梯价 / 远端价格目录，可直接作为「是否已定价」的判断依据；`Pricing.cost()` 对未定价模型返回 `nil`（而非 0），聚合到 `UsageBucket.costUSD` 时未定价按 0 处理、不污染总成本。

### F5 对话明细（P0，核心新功能）

位置：统计 tab 侧栏「Breakdown / 明细」（现为灰显占位，本期启用）。顶部筛选（服务 / 模型 / 时间范围）继续生效。

**列表**（表格，默认按最近活动倒序）：

| 列 | 内容 |
|---|---|
| 时间 | 会话在所选范围内的最近活动时间 |
| 服务 | Codex / Claude 品牌识别（Codex 排前的全局规则不适用于列表排序，列表按时间/成本排） |
| 项目 | `cwd` 最后一段路径；悬浮显示完整路径 |
| 对话标题 | 首条用户消息截断（≤ 80 字符，单行省略）；提取不到时显示 `（无标题）` |
| 请求数 | 范围内 |
| Tokens | 范围内真实消耗（紧凑格式） |
| 成本 | 范围内，$，两位小数 |

- 列表数字口径：**只统计所选时间范围内发生的消耗**（跨天长会话只计范围内部分），保证列表合计与总览一致。
- 排序：支持按时间 / Tokens / 成本点击列头切换。
- 数量控制：默认展示前 200 行 +「显示更多」；空状态文案。
- 搜索框（P1）：按项目名 / 标题子串过滤。

**详情**（点击行弹 sheet）：

- 基本信息：服务、会话 ID（可复制）、项目完整路径、git 分支（仅 Claude 有）、首次 / 最近活动时间、请求数。
- Token 细分：新增输入 / 输出 / 缓存写入 / 缓存命中 / 真实消耗合计 + 缓存命中率。
- 成本明细：输入成本 / 输出成本 / 缓存写入成本 / 缓存命中成本 / **总成本**（四项分列，对齐 cc-switch 请求详情的成本明细）。
- 按模型细分：会话内各模型一行（tokens 四项 + 成本），多模型会话（如主模型 + haiku 子调用）可看清构成。
- **注意**：详情展示的是该会话**全生命周期**数据（不受时间范围筛选影响），并在 UI 上注明「全部时间」。
- 逐请求明细（P1）：详情内「请求明细」区块，**按需**重新解析该会话源文件展示逐条请求（时间 · 模型 · 四项 token · 成本），不做全量持久化。加载中显示 spinner；解析失败给错误文案。

### F6 扫描状态与手动刷新（P1）

- 统计 tab 顶部显示上次扫描完成时间（相对时间）+「立即扫描」按钮（调用现有 `UsageService.scanNow()`，扫描中禁用并转菊花）。
- 进入 Breakdown 视图时若距上次扫描 > 60s 自动触发一次 scanNow。

### F7 自动刷新间隔（P2，可不做）

cc-switch 有页面级 5s–60s 自动刷新选择器；cc-bar 已有全局「日志扫描间隔」设置 + `@Observable` 自动驱动 UI，暂不迁移页面级选择器。

## 5. 交互与视觉要求

- 全部遵循 [设计风格.md](设计风格.md)：`ccPanel` 面板、`.monospacedDigit()` 数字、SF Symbols 图标、品牌识别色只用于 tile / 标识不用于状态着色。
- 不引入 cc-switch 的 Web 风格（玻璃卡渐变、framer-motion 式动效、彩色 MiniStat 卡片背景）；细分卡用现有 KPICard / Panel 语汇。
- 双语文案：所有新增词条按设计风格.md 双语词表规范补充（如 `真实消耗 Tokens / Real tokens`、`缓存命中率 / Cache hit rate`、`请求数 / Requests`、`对话明细 / Breakdown`、`（无标题）/ (untitled)`、`未定价 / Unpriced`）。
- 数字格式沿用 `StatsFormatter`（中文 万/亿，英文 k/M/B）。
- 菜单栏 / Popover / 悬浮窗**不改**，本期只动主窗口统计 tab。

## 6. 边界与不做清单

| 不做 | 原因 |
|---|---|
| Provider（供应商）统计 | cc-bar 无代理层，JSONL 无供应商维度；「按服务」即等价维度 |
| 请求成功率 / 状态码 / 延迟 | JSONL 无此数据（cc-switch 靠代理拿到） |
| 全量逐请求日志持久化（cc-switch 的 RequestLogTable） | 存储膨胀且价值低；对话详情内按需解析源文件替代（F5-P1） |
| 定价配置 UI（cc-switch 的 PricingConfigPanel / models.dev 选择器） | cc-bar 已定策略：价格「内置表兜底 + LiteLLM/models.dev 远端目录后台自动更新」+ 指纹失效自动重算 + 设置页强制重算，用户不可见、无需配置，维护成本更低（远端自动更新详见 [技术实现.md](技术实现.md) §7.5） |
| 多账号维度用量拆分 | JSONL 不含账号标识 |
| 菜单栏 / 悬浮窗展示对话明细 | 空间不适合，入口统一在主窗口 |

## 7. 待确认项（实施前需产品拍板）

1. **逐请求明细的形态**：按「详情内按需解析」设计（F5-P1）。若想要 cc-switch 那种独立的全量「请求日志」Tab（可跨会话翻页），存储方案要重做，请明确。
2. **趋势图成本的呈现**：采用「Tokens / 成本」切换而非同图双轴（SwiftUI Charts 限制），是否接受。
3. **子任务 / 自动化会话**：Claude 的 subagent 会话、Codex 的 automation 会话会以独立对话出现在列表里（标题可能是注入的指令文本），本期不做识别合并，是否接受。
4. **对话列表的默认时间范围**：跟随顶部范围筛选（默认「今天」）。若希望 Breakdown 默认「全部」，请明确。

## 8. 验收标准

1. **对账一致性**：同一筛选条件下，总览四项细分之和 = 真实消耗大数字；对话列表（含「显示更多」后全部行）的 tokens / 成本合计 = 总览对应值；按模型明细合计亦相等。
2. **与既有口径不回归**：升级后「今天」范围的总 tokens / 总成本与升级前一致（允许因请求数补扫导致的全量重算差异，需在实施记录中说明）；菜单栏当日成本不变。
3. **外部对账（抽样）**：任选一个 Claude 会话，详情页四项 token 与用 `jq` 手工统计该 JSONL 文件去重后的 usage 合计一致。
4. **筛选联动**：切服务清模型筛选；模型筛选下拉只列有数据的模型；总览 / 趋势 / 明细三处同步变化。
5. **性能**：全量重扫（首次升级触发）在既有日志量级下完成时间与现状同数量级；Breakdown 列表打开无可感知卡顿；详情逐请求解析异步、不阻塞主线程。
6. **N/A 语义**：Codex 筛选下缓存写入显示 N/A 而非 0；混合筛选下有偏低提示。
7. **视觉**：通过设计风格.md 自查（面板、字体、数字等宽、双语、空状态）。
