概览

本稿覆盖 cc-bar 多 Provider 改造后的全部界面，样例数据与真实数据模型一致：两个 Codex 账号（默认登录 + ccpm profile）、两个 Claude Code 账号、通过 ccpm profile 发现的 Kimi Code、GLM Coding Plan、Ollama Cloud 各一个。页面用同一份样例数据渲染，改样例即可同步所有界面。

本次改动的核心
1. 统一账号模型：Provider + ProviderDescriptor + MonitoredAccount，AppState 只有一个账号列表与一个按账号 id 键控的额度字典。
2. 第三方账号只从 ccpm profile 发现（provider 字段 + keystore），cc-bar 不提供独立填 key 入口。
3. 菜单卡对齐 codexbar：每个窗口一段（标题、进度条、剩余 % + 重置倒计时、Pace），后接 Cost / Tokens 段；不折叠，每个账号都是完整卡片。
4. 菜单栏按 provider 勾选，新增「仅显示最低」模式；HUD 每 provider 一行。
阅读提示
· 颜色规则不变：识别色只用于 tile，额度状态色按剩余比例四档（>50% 灰、20~50% 黄、<20% 橙、0 红）。
· Kimi Code 窗口带请求数明细（139/200 requests），GLM 带额度明细，Ollama Cloud 主窗是月额度（$7.50 of $60）。
· Codex Pro 20x 现在只有周窗口（wham/usage 的 primary_window.limit_window_seconds = 604800，secondary_window = null），卡片只显示 Weekly 一段；窗口种类按 limit_window_seconds 判定，不再按位置硬编码。
· 所有文案都是中英双语选词，本稿默认显示英文口径，方便和 codexbar 对照。
· 最后两节是本稿的重点：ccpm 联动流程，以及 codexbar 有哪些能力能迁进 cc-bar / ccpm。

① 菜单栏

每个启用的 provider 一段（logo + 百分比），顺序固定 Codex → Claude → Kimi → GLM → Ollama。新增「仅显示最低」模式，只画剩余最低的那个 provider，解决五个 provider 把菜单栏撑宽的问题。「主/副窗口」切换对所有段同时生效。

② Popover

宽 340pt。Header 保留原有一排按钮。每个 provider 一个分区，多账号时有分区标题；每个账号一张完整卡片（不折叠）。卡片结构对齐 codexbar：头部（tile、名称、身份、更新时间、计划），每个窗口一段，Pace 一行，最后 Cost / Tokens 段。

与 codexbar 的对应关系
· codexbar「Session / Weekly / Sonnet」= cc-bar 的 primary / secondary / extra 窗口，标题来自 QuotaWindowKind.laneTitle。
· codexbar「2% used · Resets in 3h 53m」= cc-bar「98% left · resets in 3h 53m」（cc-bar 一直显示剩余口径）。

⑦ ccpm 联动

第三方 provider 的唯一入口是 ccpm profile。ccpm 负责「登记 + 存 key + 启动时注入」，cc-bar 负责「发现 + 查额度 + 扫本地用量」。两边只通过 ~/.ccpm/config.json、macOS Keychain 与 profile 目录交换信息，没有进程间通信。

映射表 runtime × provider × auth → cc-bar 凭据
codex + oauth → Codex OAuth（读 auth.json，与默认/导入账号同身份时镜像）
claude + anthropic + oauth → Claude OAuth（profile 专属 Keychain service）
claude + anthropic + api_key → 不查额度，只扫本地用量
claude + kimi / glm + api_key → keystore key + base URL
claude + ollama + api_key → cc-bar Keychain 里的 cookie

⑧ codexbar 能力迁移矩阵

逐项对照 codexbar 的能力，判断能不能、值不值得迁进 cc-bar 或 ccpm。判定依据：cc-bar 的边界（零依赖、不做浏览器 cookie 自动导入、不做 App 内登录、只读监控）和 ccpm 的定位（profile 管理 CLI）。

已落地 本次改造已实现 建议迁移 收益明确、成本可控 可选 有价值但非必需，或成本较高 不迁移 与边界冲突或收益低
