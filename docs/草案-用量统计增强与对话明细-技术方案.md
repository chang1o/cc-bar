# 用量统计增强草案 · 后续技术候选

> 状态：原宽范围方案已收窄。当前对话能力的实现说明已经并入 [技术实现.md](技术实现.md) §7，界面规格见 [界面布局.md](界面布局.md) §3.6。

## 当前已采用的结构

- 一次 JSONL 增量扫描同时产出日聚合和对话聚合。
- `ConversationAggregator` 按 `(conversationKey, day, model)` 聚合，`ConversationRollupCache` 独立持久化。
- scan-state、日聚合和对话聚合共享 generationID；聚合结果先落盘，watermark 最后提交，错代或保存失败时全量重建。
- 无新增用量或档案变化的扫描不重复编码、写入完整对话缓存；watermark 也未变化时完全不写盘。
- Codex 用稳定 session ID 维护 watermark，避免 rollout 归档移动后重复计数。
- Claude 相同 sessionId 的主文件和 subagents 合并，并继续按 message.id 全局去重。
- `Pricing.costBreakdown()` 提供四项 Decimal 成本，未定价继续用 nil 语义。
- UI 使用列表＋右侧完整生命周期详情，刷新只触发本地 `UsageService.scanNow()`。

## 暂不采用

- 不把日桶升级为小时桶。
- 不改造 Overview Hero、趋势图或模型筛选。
- 不持久化逐请求明细。
- 不引入 SQLite、SwiftData或第三方依赖。

后续候选如需实施，应另开需求并基于当时的数据量和界面现状重新设计。
