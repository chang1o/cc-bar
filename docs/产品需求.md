# cc-bar 产品需求

> 描述当前已交付版本的功能范围与边界。新需求迭代时以本文为准；与代码不一致以代码为准并同步回这里。

---

## 0. 产品定位

- **形态**：常驻菜单栏的小工具（Accessory App，不占 Dock）。
- **平台**：macOS 14 Sonoma+（依赖 SwiftUI `MenuBarExtra(.window)`、`@Observable`、`SMAppService`）。
- **设计**：以 macOS HIG 为底座，关键信息层（百分比、进度、KPI、HUD）按设计稿落地自绘组件；非关键层（Picker / Toggle / DatePicker / TabView / Material）全部用系统默认。
- **一句话价值**：装上它 → 不打开 CLI 也能随时看到 Codex / Claude Code / Kimi Code / GLM Coding Plan / Ollama Cloud 还剩多少额度、消耗节奏是否超前、今天和本周花了多少钱（或用了多少 token）。

## 1. 账号自动识别

- 支持的 provider 固定为 5 个，显示顺序 `Codex → Claude Code → Kimi Code → GLM Coding Plan → Ollama Cloud`：

| Provider | 厂商 | 主窗口 | 副窗口 | 本地费用 | 额度来源 |
|---|---|---|---|---|---|
| Codex | OpenAI | 5H（部分套餐无） | WK | 有 | `wham/usage`（OAuth）；窗口种类按 `limit_window_seconds` 判定，Pro 20x 只有周窗 |
| Claude Code | Anthropic | 5H | WK（+ Opus / Sonnet 周窗） | 有 | `oauth/usage`（OAuth） |
| Kimi Code | Moonshot | 5H 速率 | WK 请求数 | 无，只显示 token | Kimi Code API（API key） |
| GLM Coding Plan | Zhipu | 5H | WK（+ MCP 月窗） | 无 | BigModel / z.ai quota API（API key） |
| Ollama Cloud | Ollama | MO | WK | 无 | ollama.com 设置页（手动 Cookie） |

- 启动与每次刷新前都重新发现账号，产出统一的 `MonitoredAccount` 列表（`AccountCatalog.discover()`）：
  - 默认 Codex：`~/.codex/auth.json`（OAuth 模式，解析 JWT 拿邮箱 / plan / accountId）。
  - 默认 Claude：先读 `~/.claude/.credentials.json`；不存在则读 macOS Keychain 通用密码项 `Claude Code-credentials`。邮箱兜底从 `~/.claude.json` 顶层 `oauthAccount.emailAddress` 读取。
  - 手动导入的 Codex 账号：沿用「其他 Codex 账号」列表，只有勾选显示的进入监控。
  - ccpm profiles：读取 `~/.ccpm/config.json`（尊重 `CCPM_HOME`）的 `runtime` / `provider` / `auth_method` / `env`，按下表映射：

| runtime | provider | auth_method | 结果 |
|---|---|---|---|
| codex | — | oauth | Codex OAuth，读 `<dir>/auth.json`；与默认或导入账号同身份时镜像其额度 |
| codex | — | api_key | 只做本地用量，不查额度 |
| claude | 缺省 / anthropic | oauth | Claude OAuth，用 profile 专属 Keychain service `Claude Code-credentials-<sha256(abs(dir))[:8]>`，兜底 `<dir>/.credentials.json` |
| claude | anthropic | api_key | 只做本地用量，不查额度 |
| claude | kimi / glm | api_key | API key 从 ccpm keystore 读取；额度接口的 host 跟随 `env.ANTHROPIC_BASE_URL`，缺失时用 provider 默认 |
| claude | ollama | api_key | 额度靠用户在设置里粘贴的 ollama.com Cookie 头（存 cc-bar 自己的 Keychain），未粘贴时提示 |

  - `provider` 字段由 ccpm fork 的 `ccpm add <name> --provider kimi|glm|ollama` 写入；ccpm 启动这些 profile 时把 key 注入为 `ANTHROPIC_AUTH_TOKEN`（Anthropic 仍为 `ANTHROPIC_API_KEY`）。cc-bar 只认这个字段，不按 URL 猜 provider。
- 不做 App 内登录流程。前提：用户已经在终端跑过 `codex login` / `claude` 登录，或用 ccpm 建好了 profile。
- 用户可在「设置 → 账号」勾选要显示的 provider；关闭后该 provider 的所有账号在菜单栏、Popover、悬浮窗、统计中均不出现，也不查询对应接口。
- 首次启动若不存在 `~/.claude/.credentials.json`，且尚未提示过，会先弹一次说明性 Alert（"接下来 macOS 会弹 Keychain 授权窗口，请选择始终允许"），再触发系统 Keychain 弹窗。ccpm keystore 的条目由 `security` CLI 创建，cc-bar 用同一 CLI 读取不会弹窗。

## 2. 菜单栏标签

- 标签是模板图像（template NSImage），自适应深浅菜单栏。
- 每个 provider 一段，顺序固定为 provider 顺序（Codex 永远在 Claude 前）。
- 每段为 `<provider logo>  <百分比>`：
  - Logo 用项目内置的 `Resources/Logos/<provider>.svg`（不是 SF Symbol）。
  - 百分比用 `monospacedDigit`。
  - 图标样式选「量表」时不画百分比文字，改在 logo 右侧画一条 5×14pt 竖向量表，按剩余比例自底向上填充；额度周期为「两者」时画两条（主、副）。
- 设置项：
  - 显示哪些 provider（逐个开关；未发现账号或在「账号」里关闭的 provider 不可勾选）。
  - 显示模式：`全部`（每个勾选的 provider 一段）/ `仅最低`（只画当前窗口剩余最低的那个 provider）。
  - 额度周期：主窗口 / 副窗口 / 两者（`5h/1w` 斜杠拼接）。主副语义按 provider 解释：Codex / Claude / Kimi / GLM 为 5H / WK，Ollama Cloud 为 MO / WK。
  - 图标样式：`百分比`（默认）/ `量表`。
- 每段显示该 provider 所有账号中剩余额度最低的窗口（默认登录、导入账号、ccpm profiles 合并），用作多账号监控的聚合告警值。账号只有周窗时（Codex Pro 20x），主窗口即周窗，段文字显示 `WK`。
- 都关闭时仍保留一个占位 logo，避免菜单栏完全消失。

## 3. Popover 总览

- 点击菜单栏图标弹出宽 340pt 的窗口。
- 内容按 provider 顺序分组，每个账号一张卡片（参考 CodexBar 的 menu card）；某个 provider 有多个账号时先显示分区标题（`<PROVIDER> ACCOUNTS · n`）。
- Header 一行：标题「Usage / 用量」+ 副标题（最近一次刷新相对时间）+ 状态点（live / stale / offline）+ 主副窗口切换按钮（按钮文字取第一个可见 provider 的当前窗口标签，如 `5H` / `WK` / `MO`；只决定菜单栏与悬浮窗显示哪个窗口，卡片始终列出全部窗口）+ 一级图标按钮（刷新 / 统计 / 设置 / 退出）。
- 任一可见账号的主或副窗口剩余额度 `≤20%` 时，Header 下方显示一条紧凑风险摘要，只展示当前最紧张的账号、窗口、剩余百分比与重置时间；隐私模式下隐藏账号别名 / 邮箱。
- 每张卡片：
  - 头部：provider tile + provider 名 + 副标题（来源 · 账号 · plan；API key 类账号显示接口 host）+ 第二行刷新状态（`Updated 32s ago` / `Refreshing…` / `Waiting for first refresh` / `Refresh failed`，非 API 来源追加 `cache` / `Claude CLI`）+ 右侧 plan 胶囊 + 服务状态圆点。
  - 每个额度窗口一段（快照里的全部窗口，主窗口在前；无快照时按 descriptor 的主副窗口画占位；Codex Pro 20x 这类只有周窗的账号只画一段 Weekly，不会出现被误标为 5H 的窗口）：标题（`Session · 5h` / `Weekly` / `Monthly` / `Opus · weekly` / `Sonnet · weekly` / `MCP · monthly` / `Extra usage · monthly`）+ 右侧明细文本（Kimi `139/200 requests`、Ollama `$7.50 of $60`、Claude 超额 `$12.34 / $2000.00`）+ 进度条 + `N% left` + 重置倒计时（hover 切换绝对时间）+ 节奏行（窗口有重置时间且已过去 ≥3% 时显示 `Pace: on track / ahead +12% / behind -8%`，再接 `runs out in 1h20m` 或 `lasts to reset`）。
  - 本地用量段（有扫描目录的账号才显示）：计费 provider 标题「Cost」，每行 `$N · N tokens`；不计费 provider 标题「Tokens」，只显示 token；三行为今日 / 本周 / 最近 30 天。
  - 操作行：`Dashboard`（打开该 provider 的用量控制台；GLM 按接口 host 选 bigmodel.cn 或 z.ai）· `Status`（只有 Codex / Claude 有状态页）· `Terminal`（在 Terminal.app 里跑 `ccpm run <profile>`，首次会弹一次 macOS 自动化授权）· `Set default`（跑 `ccpm set-default <profile>`，成功后重新发现账号）。后两项只出现在 Claude 运行时的 ccpm 账号上，当前默认 profile 不显示 Set default；失败原因以橙色小字显示在行下。
  - 失败时底部一行短文案（橙色）；Ollama 未粘贴 Cookie 时提示去设置里粘贴。
- 没有任何可见 provider 时显示"未启用任何服务 / 到「设置 → 账号」开启"占位。
- 状态点阈值：以当前额度刷新间隔为基准，age ≤ 1.5× 间隔为 live，≤ 3× 为 stale，超过为 offline。

## 4. 桌面悬浮窗（Floating HUD）

- 设置里可勾选「显示悬浮窗」。
- 每个勾选的 provider 一行 pill（18pt tile + 进度条 + 窗口标签 + 大字百分比），显示该 provider 聚合后的当前窗口（主 / 副跟随菜单栏额度周期），多账号时取剩余最低者。
- 行可分别开关，结果只显示部分行 / 全部隐藏。
- 样式：14pt 圆角 + `.popover` material + 0.5pt hairline 描边；无标题栏；不抢焦点；可拖动；始终置顶。
- 位置记忆：拖动后写回 UserDefaults；屏幕外重启时回落到默认右上角。
- 拖到距屏幕边缘 20pt 以内自动吸附到该边。

## 5. 自动后台刷新

- 后台两条独立循环：
  - 额度 API 循环：默认 2 分钟，可选「1m / 2m / 3m / 5m / 10m」。
  - 本地 JSONL 扫描循环：默认 2 分钟，可选「1m / 2m / 3m / 5m / 10m」。
- 端点：

| Provider | 请求 |
|---|---|
| Codex | `GET https://chatgpt.com/backend-api/wham/usage`，带 `ChatGPT-Account-Id` 头 |
| Claude | `GET https://api.anthropic.com/api/oauth/usage`，带 `anthropic-beta: oauth-2025-04-20` |
| Kimi Code | `GET {ANTHROPIC_BASE_URL 的 host}/coding/v1/usages`，`Authorization: Bearer <key>` |
| GLM | `GET {ANTHROPIC_BASE_URL 的 host}/api/monitor/usage/quota/limit`，`Authorization: Bearer <key>` |
| Ollama Cloud | `GET https://ollama.com/settings`，带用户粘贴的 `Cookie` 头，解析 HTML |

- 刷新引擎按账号（`AccountID`）独立调度：每个账号自己的快照、来源、错误、刷新状态与退避窗口；镜像账号不发请求，直接读被镜像账号的状态。
- 限流策略：
  - 同一账号两次成功之间至少 60 秒，周期性触发若间隔不足直接跳过。
  - 收到 429 后该账号进入 10 分钟退避，期间所有请求短路。
  - 手动「立即刷新」可绕过 60s 节流但仍遵守 429 退避。
  - 同时最多 3 个账号并发请求。
- provider 在「设置 → 账号」关闭后，其所有账号与 statuspage 状态均停止后台查询；已存在缓存保留，重新开启后继续刷新。
- Claude API 失败且**完全没有可展示缓存**时，手动刷新会触发一次 Claude CLI 兜底（仅默认 Claude 登录；启动 `claude` 进程，向其 stdin 写入 `/usage`，解析输出），CLI 兜底也有独立 10 分钟冷却。
- Token 续期：Codex / Claude 双方均在 access_token 临期时用 refresh_token 自动续期，并把新 token 写回原存储位置；ccpm Codex 只写回自己的 `auth.json`，ccpm Claude 只写回 profile 专属 Keychain service / credentials 文件。Kimi / GLM / Ollama 无续期概念。
- 启动行为：先读本地额度缓存让 UI 立刻有数；账号发现完成后立即发一次额度刷新（缓存不足 60s 的账号被节流跳过），之后由调度器节奏触发；网络失败保留已有快照，仅以小字提示。
- 额度通知（默认关，「设置 → 刷新 → 额度通知」开启，首次发送时申请系统通知权限）：只在 API 成功快照上评估，逐窗口比较新旧快照：剩余从 >20% 落到 ≤20% 通知「低额」，从 >0 落到 0 通知「用尽」，重置时间向后移动超过 1 小时且剩余回升 ≥30 个百分点通知「已重置」（只对 5H / 周 / 月窗口）。同一账号、窗口、事件在当前窗口周期内只通知一次；重置事件会清掉该窗口的低额 / 用尽记忆。

## 6. 本地用量统计

- 数据源：纯本地 JSONL，**额度 API 不返回历史数据**。每个监控账号带自己的扫描根目录：
  - 默认 Claude：`~/.claude/projects/**/*.jsonl`；ccpm Claude 运行时 profile（含 Kimi / GLM / Ollama）：`<profileDir>/projects/**/*.jsonl`。解析 `type=assistant` 行，同一 `message.id` 跨文件、跨账号全局去重（sidechain / subagent 会重复引用同一条），seen 集合上限 20000。
  - 默认 Codex：`~/.codex/sessions/**/*.jsonl` + `~/.codex/archived_sessions/**/*.jsonl`；ccpm Codex profile：`<profileDir>/sessions` + `<profileDir>/archived_sessions`。按 `turn_context` 提供的当前 model 给随后的 `event_msg/token_count` 打标签；token 用 `payload.info.last_token_usage`，billable input = `input_tokens − cached_input_tokens`。
  - 手动导入的 Codex 账号没有本地日志，不参与统计。
- 增量逻辑：每个文件按 `mtime + offset` 维护 watermark，未变化直接跳过；文件被截断时 offset 归零重扫，去重由全局 seen 兜底。各账号并行扫描（最多 4 个），结果合并。
- 聚合：按 `(day, accountId, provider, model)` 四元组在内存中累加；持久化到 `usage-rollup.json`。
- 价格表：在 `Core/Usage/Pricing.swift` 中硬编码，对齐 cc-switch / CodexBar 实测值。命中不到的模型 cost 计 0，token 仍记录；Kimi / GLM / Ollama 的模型没有公开单价，UI 对这些 provider 只显示 token、不显示费用（`ProviderDescriptor.supportsCost == false`）。模型名归一化：剥 `openai/` 前缀、`@YYYYMMDD` 或 `-YYYY-MM-DD` 日期后缀。

## 7. 主窗口 — 统计

- 主窗口为普通 macOS 窗口，最小 800×520，含顶部 TabView：统计 / 设置。
- 入口：Popover 的统计 / 设置图标、菜单栏的 ⌘1 / ⌘, 命令、⌘R 触发立即刷新。
- 统计 tab：
  - 侧栏：服务过滤（All + 每个可见 provider），View 切换（Overview / Timeline / Breakdown）。服务过滤与「设置 → 账号」全局开关共同决定可见数据；被关闭的 provider 不会出现在任何面板中。
  - 顶部 segmented Picker：Today / Yesterday / Week / Month / Year / 7d / 30d / All / Custom。
  - 自定义：两个 DatePicker（仅在 Custom 时出现）。
  - KPI 一排：总 tokens / 总花费（仅当可见 provider 中有计费者）/ 每个可见 provider 一张（计费 provider 显示花费，其余显示 tokens）；每张带相对上一同长度区间的 delta 百分比。
  - 日趋势：当前可见 provider 的堆叠柱状图，用 SwiftUI Charts；可见 provider 全部不计费时按 tokens 画。
  - 服务占比：水平条形 + KPI 文本，占比按花费或 tokens（同上规则）。
  - 当前额度：圆环展示每个可见 provider 聚合后的主 / 副窗口剩余百分比，标签用窗口种类（5H / WK / MO），颜色按状态色逻辑。
  - 按模型明细：按 provider 分组列出 model · tokens · cost（不计费 provider 显示 tokens）。
  - Timeline：展示今日每个可见账号的 5H 额度变动（没有 5H 窗口的 provider 用主窗口）。只显示发生变化的时间点；同值刷新仅更新基准，不进入曲线和表格。每个账号独立分区，顺序为 provider 顺序 × 账号顺序（默认登录 → 导入 → ccpm）。
  - Breakdown：按当前日期范围、服务筛选和账号开关展示 day / provider / account / model 粒度的本地用量表，列出 input / output / cache / total tokens / cost；账号列仅在有多个账号时出现，不计费 provider 的 cost 显示 `—`，表头可点击排序。

## 9. 首次启动引导（Onboarding）

- 首次启动检测到 `SettingsStore.didCompleteOnboarding == false` 时弹出 4 步窗口（620×520，`.regularMaterial`）：
  1. Welcome：标题 + 简介。
  2. Detect accounts：按 provider 列出自动识别结果（tile、来源路径、邮箱、plan）；已识别的 provider 可直接勾选是否显示，写入 `enabledProviders`。信息卡明确说明 cc-bar 读取本机凭据，只请求各 provider 自己的官方 API，不会把凭据发送到其他服务器。
  3. Configure：菜单栏按 provider 勾选 + 悬浮窗开关一次性设置。
  4. Ready：完成，按钮可直接进入"统计"或关闭。
- 完成后写入 `didCompleteOnboarding=true`，后续启动不再展示。

## 11. 持久化文件清单

| 位置 | 文件 | 内容 |
|---|---|---|
| `~/Library/Application Support/CCBar/` | `quota-cache.json` (v2) | 每个监控账号的额度快照，键为 `AccountID`（如 `kimi:ccpm:work`）。**跨工具契约**：ccpm 的 `statusline` 在 Claude Code 没给 `rate_limits` 时读这份文件（键 `<provider>:ccpm:<profile>`，`updatedAt` 为 Apple 参考时间秒数，超过 30 分钟视为过期），改格式必须升版本号 |
| `~/Library/Application Support/CCBar/` | `quota-history-today.json` (v2) | 今日 5H 额度变动事件，键为 `AccountID` |
| `~/Library/Application Support/CCBar/` | `usage-rollup.json` (v5) | (day, accountId, provider, model) 聚合桶 |
| `~/Library/Caches/CCBar/` | `scan-state.json` (v5) | 每个 JSONL 文件的 mtime + offset watermark（所有账号共用一张表）、Codex 当前模型、Claude 跨文件 seen ID 集 |
| macOS Keychain | `com.cc-bar.ollama.cookie` / account = profile 名 | 用户粘贴的 ollama.com Cookie 头 |
| `UserDefaults` | `ccbar.settings.*` | 所有设置项（provider 集合 `enabledProviders` / `menuBarProviders` / `floatingProviders`、`menuBarMode`、`menuBarStyle`、`quotaNotifications` 等）+ 悬浮窗 frame + 引导/Keychain 弹窗标记；首次启动从旧的 `showCodex` / `showClaude` 布尔键迁移一次 |

版本号变化时直接丢弃旧文件：缓存重新拉取，汇总触发一次全量重扫。

## 12. 一期明确不做

- 不做 App 内 OAuth 登录。
- 不做浏览器 Cookie **自动**导入；Ollama Cloud 走手动粘贴 Cookie 头。
- 不做 WebView 抓 dashboard DOM。
- 不做 Gemini / Copilot；Kimi Code / GLM / Ollama Cloud 之外的第三方不做。
- 不做 GLM team scope、Kimi 网页端增强、z.ai 全球站余额。
- 不上 Mac App Store（沙盒会拦住 `~/.claude` / `~/.codex` / `~/.ccpm` 读取）。
- 不做组织级 Admin API。
- 不做邮件 / 推送等外部渠道的额度告警；本地 macOS 通知已实现（默认关，见 §5）。

`claude /usage` 的 CLI 兜底当时被列为「一期不做」，实际作为最后一道兜底已经做了；只在 Claude API 失败且无可展示缓存的手动刷新场景启用，不替代主路径。

## 13. 风险 / 待持续关注

1. **非公开接口稳定性**：`wham/usage` / `oauth/usage` 字段可能随时调整，解析器需要保持容错。
2. **Keychain 弹窗**：首次读 `Claude Code-credentials` 系统会弹一次授权窗，引导文案已加。
3. **价格表漂移**：当前对齐 cc-switch / CodexBar 2026 上半年价位；模型迭代后需要同步。
4. **JSONL 量级**：长期使用后 `~/.claude/projects` 可达数百 MB；增量 watermark + seen ID 上限保证启动 / 扫描时间可控，但 seen 集合上限 20000 时若历史窗口超过该长度会有边缘重复风险。
5. **签名与公证**：发布前需 Apple Developer 证书；当前开发期未签名，README 标注「右键打开」。
6. **第三方接口漂移**：Kimi Code `usages` 与 GLM `quota/limit` 为各厂商控制台接口，字段可能调整；Ollama Cloud 额度完全依赖 `ollama.com/settings` 的 HTML 结构，页面改版即失效，解析器需要随之更新（`scripts/selfcheck.sh` 内固定了新旧两版页面样例）。
7. **ccpm 字段依赖**：`provider` 字段只存在于 ccpm fork；用上游 ccpm 建的第三方 profile 不带该字段，会被当作 Anthropic API key profile（只做本地用量）。
