# cc-bar 产品需求

> 描述当前已交付版本的功能范围与边界。新需求迭代时以本文为准；与代码不一致以代码为准并同步回这里。

---

## 0. 产品定位

- **形态**：常驻菜单栏的小工具（Accessory App，默认不占 Dock；打开主窗口期间临时显示 Dock 图标，关闭后恢复）。
- **平台**：macOS 14 Sonoma+（依赖 SwiftUI `MenuBarExtra(.window)`、`@Observable`、`SMAppService`）。
- **设计**：以 macOS HIG 为底座，关键信息层（百分比、进度、KPI、HUD）按设计稿落地自绘组件；非关键层（Picker / Toggle / DatePicker / TabView / Material）全部用系统默认。
- **一句话价值**：装上它 → 不打开 CLI 也能随时看到 Codex / Claude Code / Antigravity 当前主要额度与周窗口额度，并查看 Codex / Claude Code / Pi / OpenCode 的本地 Token 与费用。

---

## 1. 账号自动识别

- 启动时扫描本机已有的 Codex / Claude Code 凭据与 Antigravity 安装状态：
  - Codex：`~/.codex/auth.json`。支持两种凭据形态：① OAuth 模式（`tokens.*`，解析 JWT 拿邮箱 / plan / accountId，到期自动续期）；② personal access token 模式（顶层 `personal_access_token`，即 ChatGPT Team/Enterprise 后台创建的 Codex 访问令牌，不透明、不续期，身份由 `wham/usage` 响应回填）。导入「其他 Codex 账号」时也接受这两种形态的粘贴。
  - Claude：先读 `~/.claude/.credentials.json`；不存在则读 macOS Keychain 通用密码项 `Claude Code-credentials`（service name）。邮箱兜底从 `~/.claude.json` 顶层 `oauthAccount.emailAddress` 读取。
  - Antigravity：检测官方 App / IDE 的本地 `language_server`。只在进程运行时通过 loopback 读取 `Claude + GPT models` 组和 `Gemini Models` 组的 5H/WK 剩余额度（Gemini 仅在 Popover 中作为子行展示，不影响菜单栏和悬浮窗）。不读取或保存 Google OAuth 凭据。
- 不做 App 内登录流程。前提：用户已经在终端跑过 `codex login` / `claude` 登录。
- 用户可在「设置 → 账号」勾选要显示的服务；关闭后该服务在菜单栏、Popover、悬浮窗、统计中均不出现，也不查询其 API。
- 首次启动若不存在 `~/.claude/.credentials.json`，且尚未提示过，会先弹一次说明性 Alert（"接下来 macOS 会弹 Keychain 授权窗口，请选择始终允许"），再触发系统 Keychain 弹窗。

## 2. 菜单栏标签

- 标签是模板图像（template NSImage），自适应深浅菜单栏。
- 顺序固定：**Codex → Claude Code → Antigravity**。
- 每段为 `<服务 logo>  <百分比>`：
  - Logo 用项目内置的 `codex.svg` / `claude.svg` / `antigravity.svg`（菜单栏会做模板化变灰）。
  - 百分比用 `monospacedDigit`。
- 设置项：
  - 显示哪个服务（Codex / Claude / Antigravity，可分别开关）。
  - 显示哪个额度窗口：主要额度 / 周窗口 / 两者。主要额度通常是 5 小时；服务端临时只返回周额度时自动显示周额度。两者相同时只显示一次。
- 都关闭时仍保留一个占位 logo，避免菜单栏完全消失。

## 3. Popover 总览

- 点击菜单栏图标弹出宽 340pt 的窗口。
- 顺序：Codex → Claude → Antigravity（每个服务一个 block，用 Divider 分隔）。
- Header 一行：标题「Usage / 用量」+ 副标题（最近一次刷新相对时间）+ 状态点（live / stale / offline）+ 三个一级图标按钮（刷新 / 统计 / 设置）+ ⋯ kebab 菜单（退出）。
- 每个 block 字段：
  - 服务 tile + 服务名 + 副标题（Provider · Plan）。
  - 主要额度：32pt 剩余百分比 + 16pt `%` + 动态窗口标签 + 进度条 + 重置倒计时；Codex / Claude 额外显示「今日 cost」+「本周 cost」。
  - 次要额度：存在且与主要额度不重复时显示缩小版进度条；Claude 继续展示 Fable 等模型专项周额度，Antigravity 展示 GM（5h）/ GW（周）。
  - 失败时下方两行内短文案提示。
- 关闭全部服务时显示"未启用任何服务 / 到「设置 → 账号」开启"占位。
- 状态点阈值：以当前额度刷新间隔为基准，age ≤ 1.5× 间隔为 live，≤ 3× 为 stale，超过为 offline。

## 4. 桌面悬浮窗（Floating HUD）

- 设置里可勾选「显示悬浮窗」。
- 默认按已启用服务逐行展示：
  - 第一行：Codex 主要额度剩余百分比（18pt tile + 进度条 + 大字百分比）。
  - 第二行：Claude 主要额度剩余百分比。
  - 第三行：Antigravity `Claude + GPT models` 主要额度剩余百分比。
- 行可分别开关，结果只显示一行 / 全部隐藏。
- 样式：14pt 圆角 + `.popover` material + 0.5pt hairline 描边；无标题栏；不抢焦点；可拖动；始终置顶。
- 位置记忆：拖动后写回 UserDefaults；屏幕外重启时回落到默认右上角。
- 拖到距屏幕边缘 20pt 以内自动吸附到该边。

## 5. 自动后台刷新

- 后台两条独立循环：
  - 额度 API 循环：默认 2 分钟，可选「1m / 2m / 3m / 5m / 10m」。
  - 本地 JSONL 扫描循环：默认 5 分钟，可选「1m / 2m / 3m / 5m / 10m」；启动后仍立即增量扫描一次，手动刷新不受周期限制。已有用户已保存的间隔保持不变。
- 端点：
  - Codex：`GET https://chatgpt.com/backend-api/wham/usage`，带 `ChatGPT-Account-Id` 头。
  - Claude：`GET https://api.anthropic.com/api/oauth/usage`，带 `anthropic-beta: oauth-2025-04-20`。
  - Antigravity：本机 `https://127.0.0.1:<port>/exa.language_server_pb.LanguageServerService/RetrieveUserQuotaSummary`，CSRF token 仅从官方进程参数读取并保留在内存。
- 限流策略：
  - 同一服务两次成功之间至少 60 秒，周期性触发若间隔不足直接跳过。
  - 收到 429 后该服务进入 10 分钟退避，期间所有请求短路。
  - 手动「立即刷新」可绕过 60s 节流但仍遵守 429 退避。
- 手动刷新会在两种情况下触发一次 Claude CLI 兜底（启动 `claude` 进程，向其 stdin 写入 `/usage`，解析输出）：Claude API 失败且**完全没有可展示缓存**，或 Claude 凭据已过期。CLI 兜底有独立 10 分钟冷却。
- Token 续期：
  - **Codex** 在 access_token 距离过期 5 分钟内用 refresh_token 自动续期，并把新 token 写回原存储位置（`auth.json` 或 cc-bar 自己的 Keychain 条目）。发请求前会重读一次存储，若 `codex` CLI 已自行轮换过就直接采用，不拿陈腐 token 去撞服务端的重用检测。
  - **Claude 不续期**。Anthropic 的 refresh_token 一次性、刷新即轮换，cc-bar 一旦刷新就会把 Claude Code CLI / Desktop 挤下线，因此只读采用它们刷新后的结果。凭据过期时保留上一次额度快照并提示「请打开 Claude Code 刷新登录」，本地 Token / 费用统计不受影响。
- 启动行为：先读本地额度缓存让 UI 立刻有数；首次刷新由调度器节奏触发；网络或本地服务失败保留已有快照，仅以小字提示。
- Antigravity 数据源按 App → IDE 顺序回退；App 提供完整 5H/WK，IDE 兜底可能只有 5H。绝不自动启动 `agy` CLI。

## 6. 本地用量统计

- 数据源：纯本地 JSONL，**额度 API 不返回历史数据**。
  - Claude：`~/.claude/projects/**/*.jsonl`，解析 `type=assistant` 行；`message.usage.speed` 的 `standard` / `fast` 原样映射，缺失或未来新值记为未识别。同一 `message.id` 跨文件全局去重（sidechain / subagent 会重复引用同一条），seen 集合上限 20000。缓存写入原始 Tokens 继续使用 `cache_creation_input_tokens` 合计；计价时读取 `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`，分别按当前 Standard / Fast 基础输入价的 1.25× / 2× 计算。
  - Codex：`~/.codex/sessions/**/*.jsonl` + `~/.codex/archived_sessions/**/*.jsonl`，按 `turn_context` 提供的当前 model 给随后的 `event_msg/token_count` 打标签；`thread_settings_applied.thread_settings.service_tier` 的 `priority` / `fast` / `default` 分别映射为 Fast / Fast / Standard，并跨增量扫描保存当前档位。token 用 `payload.info.last_token_usage`，billable input = `input_tokens − cached_input_tokens − cache_write_tokens`。`cache_write_tokens` 兼容顶层及 token details；当前本地日志未提供时按 0，不推测。相同 `total_token_usage` 签名的重复 `token_count` 不再次入账。
  - Pi：`~/.pi/agent/sessions/**/*.jsonl`，解析 `type=message` 的 assistant 行；`message.usage` 直接提供 input / output / cacheRead / cacheWrite / totalTokens。`message.cost.total > 0` 时优先采用日志总价及有效分项；分项与总价只有 JSON 浮点尾差时保留分项并对齐总价。价格缺失或为 0 且有 Token 时，复用统一 Pricing 的在线目录 → 本地价格表补算。compaction / branch_summary 带 `usage` 时一并计入（对齐 pi `/session` 合计口径）。跨文件按 entry id + ISO 时间戳全局去重（fork / clone 复制旧行），seen 上限 20000。模型标签为 `provider/model`，速度档位恒为 Standard。
  - OpenCode：`~/.local/share/opencode/opencode.db`（SQLite，Desktop / CLI 共用，只读打开），解析 `message` 表每行的 `data` JSON；assistant 消息自带 `cost`（USD）与 `tokens{input, output, reasoning, cache{read, write}}`。`cost > 0` 时优先采用日志总价，价格表只用于估算四项费用占比并按日志总价缩放，不改变总费用；价格缺失或为 0 且有 Token 时，复用统一 Pricing 的在线目录 → 本地价格表补算，仍无价格时按 `$0` 展示。reasoning 并入 output。模型标签 `providerID/modelID`（assistant 自带字段优先，缺失时继承会话内最近 user 消息的模型）；会话标题 / 项目路径 / 分支分别来自 `session` / `workspace` 表，空标题用首条 text part 兜底。增量 watermark 为 `max(message.time_created)`（Unix 毫秒），按 message.id 全局去重，seen 上限 20000。
- Antigravity 不提供同口径的本地 Token / cost 日志，因此不进入本地用量统计、服务筛选或 Timeline。
- **Pi / OpenCode 无订阅额度**：不进入额度轮询、Popover 额度区、菜单栏、悬浮窗与 Timeline；仅在主窗口用量统计与对话页展示（两者今日花费仍计入 Popover 今日合计）。
- 增量逻辑：每个文件按 `mtime + offset` 维护 watermark，未变化直接跳过；文件被截断时 offset 归零重扫，去重由全局 seen 兜底。
- 聚合：按 `(day, app, model, speed)` 在内存中累加；持久化到 `usage-rollup.json`。总 Tokens 永远使用日志原始值，Fast 的计费等效 Tokens 按独立倍率另算，不能回写或放大总 Tokens。
- 对话聚合：同一批扫描同时按 `(conversation, day, model, speed)` 聚合并写入 `conversation-rollup.json`，不保存聊天正文。Codex 以 `session_meta.id` 为对话 ID，标题优先取 `~/.codex/session_index.jsonl`；Claude 以 `sessionId` 为对话 ID，相同 sessionId 的 subagent / sidechain 合并到主对话，标题优先取 `~/.claude/history.jsonl`；Pi 以 `type=session` 的会话 id 为对话 ID（缺失时兜底文件名 UUID）；OpenCode 以 `session.id` 为对话 ID（key 前缀 `opencode:`），标题取 `session` 表的 title。
- 对话项目归属：以规范化完整路径作为项目身份；存在的路径优先归一到 Git 根目录，Claude 同时参考 history project、主会话 cwd 与顶层项目容器，子任务目录不能覆盖主项目。已删除项目保留历史归属；用户主目录 / 根目录归为“无明确项目”，CCBar probe / wakeup 归为“CCBar 系统任务”。同名不同路径不合并。
- 对话费用是按模型 API 公开价格折算的**等值估算**，不是 Codex / Claude 订阅实际账单；无法取得可靠价格时，该部分费用按 `$0` 参与展示，不追加“未定价”标记，Tokens 和请求数仍保留。
- Fast 价格优先使用带明确档位语义的在线字段（LiteLLM 的 OpenAI Priority、models.dev 官方 provider 的 `experimental.modes.fast.cost`），命中不到再回落 `Pricing.swift` 的可指纹化本地规则；绝不把 Standard 价格当 Fast。Codex 按 Priority API 等值费率估算，ChatGPT 信用消耗倍率仍只由本地可靠规则提供；Claude 仅在 Standard/Fast 四项费率比例完全一致时允许推导等效倍率。未收录 Fast 模型以及完整输入 `>272K` 的 Codex Fast 请求保留原始 Tokens、档位和请求数，无法计算的费用按 `$0` 展示；未收录倍率时计费等效 Tokens 为 0、倍率显示 `—`。
- 价格表：GPT-5.6 与 GPT-5.5 阶梯价（完整输入 `>272,000` 时该次请求全部用长上下文价）、GPT-5.5 Pro 固定本地价（输入 / 缓存读取 / 输出为 `$30 / $30 / $180`，无缓存折扣）、Claude Sonnet 5 分段生效价等少数需要特殊规则的模型继续手工维护在 `Core/Usage/Pricing.swift`，不受远端数据影响。Claude Opus 4.6/4.7 Fast 价格仅保留用于历史日志计价。Claude 缓存写入缺少 TTL 明细时全部按默认 5m 估算；Codex 缓存写入字段本地日志未提供时费用估算为 0，不推测。其余 Standard / Fast 模型由内置价格表 + 后台自动拉取的 LiteLLM / models.dev 远端价格目录共同提供：常规 24 小时检查不变；扫描发现新的缺价 Standard/Fast 模型时立即绕过 24 小时刷新，同一 app/model/speed 30 分钟内最多尝试一次；设置页也可手动更新。新价格只在扫描安全边界提交，并自动触发相关历史用量重算。无网络或远端不可用时保留旧快照并降级为内置表，不影响离线使用。命中不到任何价格源时 token 仍记录、费用按 0 汇总。模型名归一化：剥 `openai-codex/`、`openai/`、`anthropic/`、`deepseek/`、`opencode-go/` 前缀，以及 `@YYYYMMDD` 或 `-YYYY-MM-DD` 日期后缀，本地与远端目录共用同一套规则。

## 7. 主窗口 — 统计

- 主窗口为普通 macOS 窗口，最小 1040×520，含顶部 TabView：统计 / 设置。
- 入口：Popover 的统计 / 设置图标、菜单栏的 ⌘1 / ⌘, 命令；从 Dock、应用程序、Launchpad 或 Raycast 启动 / 重新打开 CCBar 时，主窗口置前并固定切到统计 tab；⌘R 触发立即刷新。开机自动启动保持静默，首次启动仍先展示 Onboarding。
- 统计 tab：
  - 侧栏：服务过滤（All / Codex / Claude Code / Pi / OpenCode，仅列出设置中启用的服务），View 切换（Overview / Conversations / Cycles / Timeline）。Cycles 只统计 Codex / Claude 主账号，但保留全部服务筛选项；筛选选择在 Cycles 中不改变内容，切回其他视图后继续生效。
  - 顶部 segmented Picker：Today / Yesterday / Week / Month / Year / 7d / 30d / All / Custom。
  - 自定义：两个 DatePicker（仅在 Custom 时出现）。
  - KPI：总 tokens / 总花费 / 各可见服务的花费卡（Codex / Claude Code / Pi / OpenCode 按「统计服务」配置增减）一行排列；每张带相对上一同长度区间的 delta 百分比。
  - Token 拆分：保留原始总 Tokens 口径，另列 Fast 原始 Tokens、计费等效 Tokens、Fast 估算费用和占比；按服务、按模型行提供紧凑 Fast 明细。总花费及 Popover 今日/本周花费自动包含可定价的 Fast 溢价，Popover 不增加字段。
  - 日趋势：堆叠柱状图（各可见服务），用 SwiftUI Charts。
  - 服务占比：水平条形 + KPI 文本；可见服务 ≤ 3 时单行排列，超过 3 个（全开时）两列换行、每行两个对齐铺满。
  - 当前额度语义由统一 `QuotaSnapshot` 提供；紧凑入口展示主要额度，详细入口按主/次/模型专项额度展示，颜色按状态色逻辑。
  - 按提供商：跨服务按模型厂商归并（OpenAI / Anthropic / DeepSeek / OpenCode-Go / 其他），面板置于概览页最下方，所有有数据的提供商一行一个平铺展示 Tokens 与费用，右上角按费用 / Tokens / 请求数 / 名称四档排序（选哪档按哪档排、数值大的在前，「其他」恒排最后，展开的模型明细跟随同一排序键）；点击行就地展开该提供商的 Token 拆分（入 / 出 / 缓存命中 / 命中率）、来源服务标注与该提供商下按模型明细。归属规则：前缀优先（`openai/`、`openai-codex/` → OpenAI，`anthropic/` → Anthropic，`deepseek/` → DeepSeek，`opencode-go/` → OpenCode-Go 单列，便于区分 opencode 内花的钱），无前缀时按模型名关键词 / app 兜底（Codex → OpenAI、Claude → Anthropic），其余归「其他」。纯展示层推导，不改动定价与存储。
  - 按模型明细：分服务列出 model · 调用次数估算 · tokens · cost。
  - Conversations：左侧列表按所选时间范围展示对话标题、项目、服务、模型、请求数、Tokens 与 API 等值估算费用；全 Fast 对话显示 `Fast` 徽标，部分 Fast 对话显示 `Mixed`，纯 Standard 和仅未识别档位不加列表噪声。支持 Codex / Claude / Pi / OpenCode 服务筛选、单项目筛选、标题/项目搜索、最近/Tokens/费用排序和每次 200 条渐进加载。项目菜单区分正常、已不存在、无明确项目和 CCBar 系统任务。右侧详情固定展示该对话全部时间的四项 Token、缓存命中率、各速度档位的请求数/原始 Tokens、Fast 计费等效 Tokens、Standard/Fast 费用、四项最终费用、模型构成与完整时间信息。对话页刷新只扫描本地日志，不等待额度或服务状态网络请求。
  - Timeline：展示今日各账号主要额度变动。只显示发生变化的时间点；主额度类型在 5H/WK 间切换时重置该账号当天基准，不把不同窗口比较成一次涨跌。每个账号独立分区，顺序为 Codex 主账号 → Codex 副账号 → Claude Code。
  - Cycles：按 Codex / Claude 主账号真实重置窗口统计当前周周期与 5 小时周期的本机实际 Tokens、API 等值费用，并根据本机观察到的官方比例增量计算用满预估。页面同时展示 Codex / Claude × 5 小时 / 周四张 KPI 卡，按服务分成两行、每行两张等宽卡，官方实时百分比继续表达当前额度状态；不展示已结束周期、历史曲线或历史筛选。统计从功能首次启用后开始，不反推此前周期，不读取日聚合或 Claude 补录数据；账号切换按时间段隔离，Claude 用邮箱脱敏哈希区分主账号。预估仅为本机 API 等值推算，不代表官方绝对 Token / credit 上限。
  - 本地日志读取、周期重建或统计持久化真实失败时，统计页顶部显示警告，保留仍可用的已有数据，并提供“打开设置”入口让用户触发重新计算；扫描过程中会话文件被正常归档或清理不算失败、不提示误报警告，错误恢复后警告自动消失。
  - 统计服务显示配置：可在「设置 → 统计服务」勾选要计入统计的服务（Codex / Claude Code / Pi / OpenCode，默认全开）。关闭后该服务从侧栏过滤项、KPI 卡、Token 拆分、按服务、按提供商、按模型、每日用量图表与对话页中一并消失，占比分母只统计可见服务（归一化）；全部关闭时「按服务」面板显示空态引导。设置中关闭的服务仍会被扫描与入库，重新开启后历史数据照常出现。

## 13. 风险 / 待持续关注

1. **非公开接口稳定性**：`wham/usage` / `oauth/usage` / Antigravity 本地 Language Server 字段可能随时调整，解析器需要保持容错；Antigravity 升级后可能暂时显示旧缓存和接口错误。
2. **Keychain 弹窗**：首次读 `Claude Code-credentials` 系统会弹一次授权窗，引导文案已加。
3. **价格表漂移**：当前对齐 cc-switch / CodexBar 2026 上半年价位；模型迭代后需要同步。
4. **JSONL 量级**：长期使用后 `~/.claude/projects` 可达数百 MB；增量 watermark + seen ID 上限保证启动 / 扫描时间可控，但 seen 集合上限 20000 时若历史窗口超过该长度会有边缘重复风险。
5. **签名与公证**：发布前需 Apple Developer 证书；当前开发期未签名，README 标注「右键打开」。
